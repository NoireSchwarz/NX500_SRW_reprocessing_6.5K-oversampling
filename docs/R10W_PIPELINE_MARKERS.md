# R10w 原厂硬件流水线完成标记

R10v 实测确认内部安装、全宽应用和三文件保存成功。稳定196请求的 event10、bit6 各一次，首末输入绑定196/196；完整周期42.999904ms，完成后到下次提交0.477625ms。同组130条关联请求的提交→bit6 为0.033507ms，bit6→bit2 为43.024393ms。原厂注册字符串将bit6命名为 CS0 FRAME_START，bit2为 FRAME_DONE；它们是IRQ被服务的时间，不能直接称为硬件忙时间。

本版根据用户要求一次覆盖输入、EP核心/缩放/写出及CS0总完成边界，增加同请求内有间隔的密集读取，减少逐点刷卡轮次。LCAC、CFA、NR等配置函数没有提供已核验的独立逐帧完成标记，这部分保持为未拆分区间。不同模块可能流水并行或属于不同CS分支，不能把事件编号顺序当成串行处理顺序。

## 不变的相机端

R10v RTOS代码、代码块、生产者11、280字节租约、event10、bit6计数/首次时间、首末输入CImage/PA/RDMA0绑定、全宽helper均逐字节保持。没有新增RTOS代码入口、堆、SMA或图像缓冲，没有重新生成旧RTOS源码。

保留几何、蓝边、UD/QHD初始化/更新、时钟、QoS、码率、原厂IRQ使能/ACK/EOI、采样入口shell。HEVC硬件断点保持停用。

## 原厂依据

固定P7 SHA256：`f8e417cb5b55768851ba7e2b8017d3a98dc0b0c8444cc0a5061265cc08dbbf7f`。

| 分组 | 原厂标记与依据 | 解释边界 |
|---|---|---|
| 输入DMA候选 | CS0 RDMA0回调801dd1dc中的原厂日志和通知ID29 | 这是通知ID候选，尚未独立证明它等于硬件注册ID29；保留原值，排除已核验阶段统计 |
| IPC写出 | CS0 WDXI0 EOF ID5、WDXI1 EOF ID1，8017bcd4/8017bbe0的命名注册，8021bbb8的真实注册 | 当前QHD请求可能跳过这些输出DMA，未启用时不当成停滞 |
| EP读入 | CORE_RDXI0..3 EOF，事件1..4 | 两个CS的状态、使能、实际回调和注册owner分别保存 |
| EP处理 | CORE_LDC EOF10、MC M2M EOF11、MC OTF EOF12 | owner是通知对象，不是硬件锁存的图像身份 |
| EP缩放 | CORE_RSZ_OUT0..4 EOF，事件13..17 | 记录全部输出支路，未启用/已置位/未观察到明确保留 |
| EP写出 | CORE_WDXI0..4 EOF，事件5..9 | 不能凭通道编号把支路直接称为HEVC主输入 |
| 总完成 | CTRL0_CS0_FRAME_DONE ID42，bit2；实际回调801cdf6c | 同请求pending可提供等待IRQ服务的保守下界 |

EP事件由原厂 `EnableInterrupt` 801caf00..801cb880 的36个注册分支和回调中的实际owner读址交叉核验。事件0是PATH_CFG_WDMA_INT，作为旁证保留，不改称逐通道DMA退役。定义、回调、owner地址及原厂注册地址记录在 `tools/video_pipeline_stages.json`。

IRQ45的80036c78读取IPC DMA EOF状态408/40c；原厂8003679c维护其使能458/45c。IRQ44读取418并在440单独ACK。EP_A/B读取C8/CC，原厂另写50/54完成ACK。本版仅允许这些已核验状态/配置的读取，启动时额外检查四组原厂代码指纹。没有打开未参与当前流程的中断。

## 记录与时间边界

100ms环读取继续，记录312字节和容量12000保持，快读格式升级3。旧EP专用四字扩展在producer11下保存IPC DMA候选、CS0总状态、EP_A/B状态；失败读取掩码和前后完整16字RTOS头的一致性另记。环读取完整与阶段证据完整分别判断。

密集窗口最多每3秒启动一次，仅接受活动HW请求、原生输入绑定通过、单次bit6且实际回调正确的上下文。每个硬件状态向量前后保存完整16字RTOS头，另保存19项状态/使能/配置/实际回调的读取掩码和原值。原始RAM发布头或DMA配置不一致时拒绝归属，不通过放宽检查掩盖R10u/v曾观察到的跨视角差异。

窗口最多50次、请求约1ms有间隔读取，设60ms墙钟预算及4ms循环CPU预算，并为下一次100ms快读预留时间。实际调度/读取耗时会记录；预算不保证内核调用绝不会延迟，漏读和截止时间问题继续明确报告。路由收尾是固定有限读数，计入实测总CPU。

同请求的CS0 done pending真实命中、使能和回调均正确后，最多再读取两次。只有同请求、相同头且pending持续的读区间才计算等待IRQ的保守下界；跨请求、读失败、使能/回调变化或状态消失均不延长下界。

每个密集窗口前后保存EP两个CS、事件0..17的实际回调和注册owner及失败掩码。只有注册路由稳定、使能有效、输入请求关联通过且在同请求内观察到0→1的标记，才生成候选EOF时间窗。初读已置位、无基线、未启用和短脉冲漏读均不构成完成时间。EP阶段仍须后续图像/输出表面身份关联才能称为同图像完整闭环。

所有新时间窗属于Linux单调时钟，不与RTOS 26MHz tick直接相减。窗口末端和逐请求环记录以序号、HW tick和输入/输出tuple精确匹配，只有原生首末绑定也通过才计入匹配摘要。

原来停用的HEVC追踪RAM区和第三个导出文件 `hevc-flow.bin` 承载新格式NXL_PIPELINE1：128字节头、1200×256字节容量。整个采集器RAM仍为11760512字节，三文件原子保存/失败重试流程保持；旧HEVC文件继续解码，不能用旧工具解析新第三文件。记录容量用尽明确标记，100ms逐请求采集继续，无覆盖旧记录。

## 验证及实机目标

新增实际ARM读取器的有序/既有/未使能标记、前后头读失败、部分标量失败原值、同前缀不同tuple、DMA配置不一致、回调/owner失败、CPU/墙钟/50次/两次补读/容量上限及快读格式3守卫测试。解码器拒绝损坏或伪造的证据；完整采集器覆盖启动、三文件保存、冲突/失败重试、USB/相机退出保留、四组新增原厂指纹拒绝。菜单控制和旧实机文件兼容另行验证。

RTOS未变，R10v原有63组原生指令、614个事务故障点等验证通过报告作为带哈希的先前证据引用，不宣称本轮重新执行或覆盖真实硬件。新测试的OS、MMIO、缓存和时钟仍有模型，不证明实机帧率或安全性。

只做一次合并采样：照片约2秒→取景5秒→全宽录像60秒→停录取景5秒→照片模式保存。没有裁切/多码率重复测试。

若输入/缩放/写出中有可关联的完成跳变而后续总完成仍晚，可缩小候选慢区间；若pending持续，调查IRQ服务等待。若阶段被旁路、未启用、标记已置位或未捕获，明确报告观测不足，不能据零值认定DDR或某模块卡住，也不把多个并行EOF强行拆成串行耗时。
