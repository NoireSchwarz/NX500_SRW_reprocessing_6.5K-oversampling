# R10u：原厂 IPC 控制器 0 请求到成功通知的缓冲关联

R10t 实测已确认实际安装运行、FA0 成功读到 0、已注册 View owner 类型正确。稳定全宽录像 101/101 请求各一次 event10；完整周期 43.466ms，event10 到最终 IRQ 43.008ms，提交到 event10 约 6µs。owner 相同仍不等于同一图像缓冲；本版不修改已通过的 owner 读址，也不从该 6µs 推断 LDC 的真实处理时间。

## 原厂路由依据

当前请求使用控制器 0。`CBackend_IPC` 父对象 `0x8153cbec` 的六字请求由 `0x801cd554` 复制到 `0x8153d928`，输入描述符在 `0x8153d930`，输出描述符在 `0x8153d938`，活动后端在 `0x8153d964`。输入 CImage 类型为 `0x80588910`。

原厂 QHD 更新方法 `0x801cf314` 用输入对象 `+0x68` 调用原厂取物理地址方法 `0x80096a8c`，再经 `0x8017c740` / `0x8049aa20` 把该地址写入控制器 0 的 RDMA0 配置 `0x20810908`。当前请求端口字 `0x01ffff00` 的 byte7 为 1，因此跳过独立 IPC 输出 DMA 更新；那组全零输出 DMA 寄存器不能用作输出图像完成证据。

实际最终中断分发 `0x80036ae8` 的 bit2 回调为 `0x801cdf6c`，经父对象虚方法 `0x801cdbb0` 的成功分支到 `0x801cdc40`，随后才分发原厂注册的通知对象。新点选择该成功通知入口。它在最终 IRQ 后，能验证缓冲关联和通知延迟，不能将其包装成 43ms 内部的中间硬件 EOF，也不是 HEVC 提交或编码完成。

## 生产修改

保留 enabled bank0 event10 的原厂 status/mask 判定及 ACK 顺序。原厂 dispatcher 的第一条 LDR 保留，第二条 LSL 所在 `0x804bb644` 使用 BLX 进入观测，再继续原厂 ACK。最终 IRQ 的原厂 PUSH 保留，`0x80036aec` 的 MOV 使用同样方式。父成功通知的 LDR `0x801cdc40` 使用 BLX 后继续原厂调用链；这些函数在此之前已保存原始 LR。

控制器 0 触发点仍在 `0x804997b8`，原厂 STR 恰好一次。控制器 1/2 的触发代码恢复为原厂字节，不生成新的逐帧关联声明。观测只支持 NTSC/UHD30 当前路线；其他模式计数采集仍可运行，但不得冒报该路线的逐帧覆盖。

ARM 入口及 Thumb2 观测体仍放在已有 A608/B236 字节租用中。原厂 `0x804e1fbc..0x804e203b` 的 128 字节尾部、后续独立 TMC 记录器和所有保留 BX 入口不变。TMC 前五控制字保持零，没有新 RTOS 分配，也没有常驻临时 CAP；原有临时执行块仍按原厂控制台退役并归还。

HW 与成功通知两处检查父运行状态 3、输入指针对齐及保守对象读址范围 [0x82000000,0x93000000)，为 +0x6c 成员在已知 RAM 上界 0x94000000 前保留余量、CImage 精确类型、非零输入物理地址与 `0x20810908` 相等；并比较两端的输入描述符、输入 PA 与输出描述符。只读取配置地址，不读 ACK、不改变 IRQ 使能。失败不调用对象方法、不追逐越界指针、不阻断原厂通知；标记及最近错误原值留存。

## 数据与解码

producer10 / magic `0x41544c56`，固定 256 字节数据、280 字节总租用；16 字头加 4×12 字记录，保留完整 26MHz tick。每条为：seq、flags、累计 LDC、HW、最终 IRQ、首次 LDC、HW 时 owner、输入描述符、输入 PA、输出描述符、成功通知 tick、最近错误原值。

flags 低位 request/HW/IRQ/完成/取消及 LDC 标记沿用，但 bit3 现在表示新成功通知；旧早期 callback 时间不再采集。bit9/10 为 HW/成功通知绑定通过，bit11 为描述符或 PA 改变，bit12 为输入范围或输出为空，bit13 为父状态或输入类型错误，bit14 为输入 DMA 地址不符或为零。原来的 HW/IRQ 重复下界、LDC0..15精确计数、16+饱和及 owner/回调变化保持。

100ms 快读及 312 字节快读记录不变，环容量明确变为 4；覆盖计数和序号缺口都禁止“完整覆盖”结论，包含显式覆盖计数非零但当前保留记录恰好无缺口的情况。

独立 Linux 双读缓冲快照复用原重采样记录末尾 128 字节；新增 valid bit `2097152` / `NXL_IPC_LINK1`。本版不再重复采集旧 720 步幅 EP 回读扩展；旧文件仍按旧标记解析。新快照保留 12 字前后向量、读成功掩码、计时头校验、HW tick、父/后端/输入/输出类型和 RDMA0 地址。route4 的三条核验 pin 和最近拒绝记录保持，兼容 timer9/10。

解码分别报告原厂输入关联候选、独立类型上下文关联和精确同请求的快照命中。稳定模式/来源边界各排除 1 秒。只有关联通过且计时有序的请求用于缓冲时间统计；event10 仍需要独立 owner 类型、唯一命中和时序验证。旧 callback 指标不会改名套用新点；新增 IRQ→成功通知、提交→成功通知、成功通知→下一提交。

## 验证及边界

验证执行真实 ARM/Thumb2 指令、原厂请求更新与 DMA 编程、完整原厂 IRQ/EP 分发、成功通知及客户列表分发，并对照未修改原厂函数的寄存器、栈、CPSR、ACK、EOI 和客户调用结果。覆盖替换描述符/PA、错误类型/状态、空或越界指针、外来通知、饱和、取消、环/时钟回绕及每个安装写入处的真实 LCD 入口。事务回放覆盖每个目标写入的失败恢复。

时钟、外设、缓存边界、OS、日志、EOI、注册客户及停止 IRQ 驱动端点仍有模型。Unicorn2.1.4 的全局写监控会影响 Thumb IT 行为；观测存储另用执行指令的地址/操作数核验，配合受限设备写监控和整条原厂函数结果对照。关键绑定逻辑使用显式分支。

这些验证不证明相机硬件、内核、MMIO/缓存时序或帧率改善。配置地址不是硬件锁存身份；输入/输出描述符不是 HEVC 缓冲，event10 的同窗口命中也尚未证明同图像 LDC EOF。本版不改几何、UD/QHD 配方、码率、时钟或 QoS，不恢复 HEVC 断点。
