# R10r：LDC EOF 计数与对象关联

## 实机依据

R10q 的相机内部安装清单 f722b4e7ba21c521439b8bc957a1e729b11412fc7a00e16f41868812949e8f30 与包一致。VIDEO_STAGE_1794497382_508 使用 producer8，26.3004秒采样完整导出三文件；479条帧记录中476条完整，EP event7总计数与逐帧命中均为0。三次稳定路由快照均为软件／硬件掩码0x401，event7关闭、回调和owner为空。当前启用的是0与10。

录像稳定段76条有效记录，周期43.562ms、HW→最终IRQ43.097ms；前后取景周期33.400／33.291ms。剔除每十帧相位1尖峰后周期仍42.587ms。完成回调到下次HW约0.473ms。SAM_0430.MP4的151帧全部解码，画面比音频短0.934967秒。慢处尚未拆开，不重复已经无明显改善的码率试验。

## 唯一 EP 观测入口

继续使用原厂 EP_A 分发器0x804bb640，在原厂 status & software mask & bit(index) 检查通过后、原厂ACK之前观察 **bank0 event10（CORE_LDC_EOF）**。event0是PATH_CFG_WDMA_INT(CS0)，不把它当作RDMA0完成；不启用event7。

观察代码恢复寄存器、CPSR和原厂事件索引，继续0x804bb644。ACK、回调和EOI由原厂代码执行。为放入原有A608/B236字节，入口预先把原厂即将载入的event index保存为R3，返回分支由链接器计算到0x804bb644；真实原厂分发器对照覆盖该ABI。原厂尾部0x804e1fbc..0x804e203b及旧上层回调0x801cab38保持原厂字节。

## 每帧数据与计数

Producer9／magic0x39544c56，仍为256字节、8槽×7字：seq、HW、首次LDC EOF、HW时的LDC owner、最终IRQ、IPC完成回调、flags。实时头第4字保留累计LDC事件数，包括窗口外事件。首次HW把native owner保存到原有可选指针字0x817dbbdc；发布时复制到帧记录。前五个原厂控制字保持零，未扩大280字节租用，也未新增RTOS分配。

flags低位：1请求、2 HW、4最终IRQ、8完成回调、16取消、32有LDC、64计数饱和、128任一次owner或回调不匹配。bits26..29保存0～15次计数；饱和位表示16次或更多，不能误报精确15次。bits16／8分别标记HW／最终IRQ重复，它们改为2次或更多的下界，不再沿用旧格式的精确8位计数。controller仍在bits24..25。SRAM-load／CS0-start计时继续不可用。

每次LDC事件比较native owner（0x8153cb28）与HW时保存的owner，并检查port10回调槽0x817d8ae8等于原厂0x801ca2f0。变化标志保持到帧发布，即使之后恢复也不会清除。不在中断里解引用任意owner或执行对象方法。空owner、缺失或多次LDC、饱和、顺序错误与重复HW／最终IRQ都不能产生有效拆分统计。

## 对象关联依据与边界

原厂0x80114e68的_setIntr使用其当前LDC操作对象this+0xC注册event10。这个this属于当前操作策略，不能误认为固定父后端0x8142e018本身。原有路径观察器已经从0x8142f1e8读取当前操作指针。

新增route schema2仍占用Linux头内15552..16351的800字节，最多六条，每个稳定视频generation两秒后保存一次。双读并复核timer、mode/source、活动IPC后端、原厂LDC父类型、当前操作指针与类型、通知接口类型、event0/10回调和owner。操作类型对由原厂RTTI确认：Base 0x80582c38/0x80582c98，View 0x80582d10/0x80582d70，Still 0x80582da8/0x80582e08。首项是操作主类型，次项为+0xC通知接口类型。CBackend_Ldc_CS使用不同的回调成员布局，本版记录为未关联，不猜测。

分析器要求：每帧owner与每次LDC owner一致、回调匹配、单次且有序；再由同一稳定mode/source区间的类型快照确认 owner=当前操作+0xC、精确主／次类型对、原厂LDC父类型和活动IPC后端。Linux发布边界必须完整落在剔除两端各1秒后的稳定区间内。缺少任何条件就保留原始计数并排除阶段耗时。每帧owner一致性加稀疏类型快照仍不证明对象生命周期从未发生ABA变化，也不证明DMA缓冲身份或HEVC归还。

只统计首次LDC时间。若实机同一窗口常有多次LDC，先用次数和对象证据判断是否分块，不能把第一次完成冒充整帧完成。

100ms环读取、三文件保存和HEVC断点停用保持；新旧magic/version精确识别，旧文件4/6/7/8继续兼容，格式5按自身布局处理。完成状态／进度对schema9的HW重复标志单独校验。全宽几何、UD初始化/更新、缩放、蓝边、码率、时钟及QoS不因此改变。
