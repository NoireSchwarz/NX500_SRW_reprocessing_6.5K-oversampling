## 2. 必须遵守的开发原则

能利用现有素材、多次取样和电脑端计算解决的问题，不交给半黑箱相机 ISP。曲线、曝光标度、矩阵拟合、LUT 仿真和留出验证在电脑完成；相机复用已验证的原厂拍摄、SRW 和跟踪接口。

保留照片、录像、原始固件、完整备份、历史日志和用户未提交改动。不格式化、不清理、不修文件系统；不重复 100／80／70Mbps 对照。旧 SD 日志曾有 WinError1392，既不忽略，也不直接宣布它是相机故障根因。

不得批量执行旧生成／修改脚本，尤其 R10l 生成脚本会重写已回退的 RTOS 代码。目录 `work/r10k-ep-flow/` 是历史名字，不能据此判断实际版本。必要的新硬件动作必须有原厂依据、明确所有权、完成确认和恢复边界。

## 3. 当前操作语义

- EV+AEL：原菜单；EV+WiFi：开关 V‑Log；双击 EV：当前已应用 LUT 详细页。AEL+WiFi 没有新增绑定。
- 调参／选表只改草稿，OK 才装载，菜单保持打开；半按返回取景。普通 A/B 仍按“选择 B → OK 调整 → OK 准备 → 回 A 再 OK 提交”。
- 普通 LUT 非零提交默认开启影片 LUT；仍可手动关，下一次应用又默认开。冷启动不自动应用。强度全零和原厂恢复不保留无意义的视频重定向。
- Log LUT 独立分类，只在 VID 的 Log LUT 入口选择，普通 A/B 与 SRW 均不可见；Log 当前为单 A，不做普通输入与 Log 输入的并行混合。
- 正式目录 32 张：25 普通、7 V‑Log。模拟项仍排除，介绍和原资源说明随包。
- SRW 保留五项入口，无测试 Gamma 和 AUTO+COMPARE 开关；初始化并重显影准备新工作阶段。先还原 V‑Log、关闭影片 LUT，再走既有 SRW 流程。

双击判定：每次按住不超过 400ms，相邻释放／按下窗口约 420ms。按键重复不计数；组合键和其它操作打断连击。单按 EV 功能延后判定，或在下一其它操作前执行。

## 5. 实时重载的边界

RC4 取自 metol 固定提交 `b10ec8413ce5f9a03079288cb9880e4d0fac983f` 的完整单次取景加载流程：CORE RSZ_OUT1_EOF／irq14 同步，再按原顺序传输，等待 ACC 3DLUT_RD_FINISH／irq7，立即清 Access 后才记录输出。只允许六个已知表地址；原厂恢复使用本次会话前捕获的来源地址。

没有移植 metol 的视频 watcher，没有重新启用 HEVC 断点、fork／ptrace 生产采样路径。新硬件加载器额外获取 SRW 的 `run.lock`；SRW 的 `reset_live_lut` 显式跳过硬件加载，仅沿用表和指针恢复。不能把 `run.lock` 无条件加到旧 LUT guard 中，否则会打断 SRW 自己的清理交接。

表写入成功与硬件装载确认分开；失败保留 `session/reload.pending`，不发已应用收据。快捷当前页读取 `session/current`、`strength` 和 `detail-parameters`，不以草稿缓存冒充已应用状态。

Log 准备和释放期间暂缓中间 3DLUT 装载；原厂 Gamma queued epoch 确认后再作最后一次加载。恢复原厂 Gamma 优先于可选 LUT 引擎校验。原厂回调延迟时有有限等待及一次同尺寸照片命令补送，未确认必须报失败。

视频规格通过原厂 `st app nx record resolution 24f/30f` 提交，核对固件、原工具身份、唯一进程和共享 UserSpec。命令内部自带原厂 S1 GUI 刷新，菜单在事务期间不因此退出；不要再用切 P/M 曝光模式来触发更新。配置应答不等于成片几何已验收，仍用新 MP4 的尺寸／实际节拍核验。

## 6. 不得误写成已解决的研究问题

**全宽 30p**：长耗时区间缩到 bit6→bit2，后续做过 event10、IPC 控制器0、请求绑定、WDMA2 行变化、HEVC 等待链、内存和并行访存观察，但没有完成可独立复现的 RSZ2／WDMA2／HEVC／DDR 因果拆分。HEVC A/B/A 的核心激活曾反复失败，不能把未闭环的试验写作已排除 HEVC。最终优先原生 24p；不是把标签改为 24.5，也不是声称真实 30p 已修好。

**Log 标定**：SRW SOURCE／LINEAR／LIFT／LOG 和电脑拟合已为曲线提供相对证据，19 点不能继续按“节点在全线性域等距”的旧假设解释。保留已部署标定，别回退到旧假设再覆盖。工作曝光增益约 `2.5203589432187403` 是本包标度，不是通过实体灰卡独立验证的物理反射率 18%。Tab S7+ 自然模式等屏幕对照不能代替测色仪／实体灰卡。

**颜色**：用户已控制 OLED 色彩关闭、sRGB、WB；事务104恒定，不再作为变化主线。剩余约码值级差异可能含屏幕网纹、对焦、压缩和采样噪声；未稳定改善留出色块的拟合矩阵不应上机。源原色／白点、饱和裁切与原厂后处理仍有独立证据缺口。

**编码和预览**：当前是 8bit HEVC 4:2:0 的 V‑Log／V‑Gamut 兼容路线，不是官方认证或 Main10。原片颜色标签未自动切换，电脑后期应按本包输入定义赋义；不能只靠容器标签判定已正确还原。视频原色预览与 Log 写卡尚未独立分流。

## 7. RC5 验证与下一步

本轮七类检查：快捷派发、菜单／按键、真实绘制、shell＋ARM LUT、安装器、身份链、构建清单；ZIP CRC 和包 SHA 通过。11 组 shell 操作覆盖普通默认开、显式关后再应用、Log 往返、忙碌拒绝和全零原厂恢复。安装回放覆盖 RC4 升级，核心库字节和 inode 保持。

这些测试含模拟 OS、MMIO、中断、Gamma 和相机端点；不能证明内核、真实中断竞争、所有相机状态、取景无闪烁或 SRW 在任意状态均正常。用户对 RC4 的反馈是经验验收，RC5 新功能尚待单独回执。

下一步先做 `RC5_TEST_STEPS_zh.txt` 的短测：核实安装清单、EV+WiFi、双击 EV、默认影片 LUT、原厂恢复及菜单内不重复切换。没有新失败时，不追加寄存器观察点、内存策略、核心库替换或码率循环。

若失败，先读取安装日志和 RAM／SD 现有记录，分清“未装新版、快捷未命中、Gamma 未排队、DMA 未确认、菜单状态未刷新”，只修命中的一条路径。不要把缺失计时当完整覆盖，也不要把关闭 HEVC 当现成修复。
