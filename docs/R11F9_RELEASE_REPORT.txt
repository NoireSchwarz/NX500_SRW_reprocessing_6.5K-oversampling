R11f9 发布验证报告

本版修复：先只读验证现有相机进程，通过后接续；启动未就绪记录为可重试的 PENDING；不自动进入恢复模式，不替换核心库。

最终源码版本通过 68 项实际 ARM 案例：20 项库/gate 校验、22 项进程发现、18 项完整快照读取合约、5 项提示程序、3 项原厂 flock 调用 ABI。提示程序在独立目录重编译，二进制完全一致；两种只读校验器和文件散列工具与 R11f8 完全一致。
18 项真实 shell 流程使用最终 entry.sh，含恢复未完成、相机未就绪、采样未停止、旧库/内存/gate 不匹配、旧工作进程尚在运行、锁被占用、显示不可用、启动编号不可读/为空、未知旧状态、完整备份末字节损坏、恢复只读失败、两个位置真实 SIGTERM 中断及随后重试。
恢复成功用例保持同一个 boot_id，依次经历恢复仍在进行、相机尚未出现、当前进程核验通过并 VERIFIED。没有强行把测试环境的 boot_id 改成新值来满足条件。另有 7 项真实 shell 稳定性/提示退出码检查覆盖进程更换、PID 重用、检查期间启动变化与中途繁忙。
完整流程执行 2143 次生产 ARM 文件散列、104 次生产 ARM 进程/库检查，以及 13 次专用 ARM 完整快照校验：12 次通过，1 次完整读取后拒绝末字节损坏。每份均为实际相机数据、真实 157285888 字节，未缩小输入或用 Python 计算结果代替 ARM 检查。没有创建新备份或修改原备份。
旧开机链接部分迁移时注入真实终止信号，校验其恢复且根分区回到只读后，重新调用同一入口可接续通过。触发文件部分归档时中断，校验入口恢复后重试通过。旧状态、两份完整备份、相机库、模块及测试媒体均通过每次前后散列对照。

覆盖边界
实际执行的是 ARM 指令、原厂动态装载器/库、真实 shell 和主机文件/链接操作。Linux 进程、内核文件接口、systemd、图形服务、挂载与锁语义部分仍由端点模型提供。原厂恢复单元按实物提取核验，但没有在真实 PID1 或相机硬件上执行本轮流程。最终仍需相机产生 R11f9 VERIFIED 和有效采样；SD 部署本身不能证明激活成功。
1065 项历史源码/文档保持 SHA256 不变。RTOS、event10、bit6、首末绑定及 HEVC A/B/A 实验不变。不重复码率测试，不把本版入口修复当作帧率问题已解决。
SD 部署前保护基线有 3252 项元数据、2968 个散列、62 项既有枚举错误、0 个散列读取错误。部署后再次对照，结果另见部署报告。未运行修复、清理或格式化。
