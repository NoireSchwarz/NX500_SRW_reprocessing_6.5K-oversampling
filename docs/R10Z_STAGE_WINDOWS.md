# R10z 阶段观测设计与证据边界

## 依据和目标

R10y 实机录像普通帧完整周期约 42.596ms，总体约 43.706ms，其中 bit6→bit2 约 43.190ms，完成到下一请求约 0.483ms。已做的 100／80／70 码率对比几乎无变化，本版不再重复。R10y 已完成的条件性 Que VA→HAL PA 转换支持输出面关联；但映射不是逐窗口保存，内存表 B 全部超时，不能据此断言缺少连续内存或 DDR 已饱和。

本版在一个包内保留原有 RTOS producer schema 11、event10、bit6、首末输入绑定和全宽应用代码，增加 Linux 只读短窗口。只重建菜单和采集器；21 个原厂校验、RTOS 和 helper 相关路径按 R10y 哈希锁定。此前相机可用的 RTOS 二进制 SHA256 为 `bca928cd373590bf0386efb2bbe06b0b98f99c82f907f01fd9a89c0d9c4cb2a7`。

## 同一窗口收集什么

- 请求头前后完整保存；只有近期观察到请求推进且头处于有效请求状态才进入 EP 细读。停止／旧头不进入设备细读。请求序号、HW tick、输入描述符、输入 PA、输出描述符共同关联原有环端点。
- WDMA2 配置前后值、源对象及 HAL 类型、完整 HAL 描述符、结果路径计数。Que slot 用计数选候选，再验证实际 slot 索引、状态、类型、payload、时间戳和代际；不把计数取模本身当作关联证明。
- 输出面 Y 第 0／1080／2159 行、UV 第 1079 行，各取列偏移 16 处的 16 字节指纹。仅验证过的 UHD WDMA2 配置和物理 RAM 范围允许读取；不读写像素以外的未知区域，也不更改设备状态。指纹变化只圈定可见写入，不证明整帧 EOF、唯一写入者或没有后续写入。静止画面或缓存可见性会造成漏观测。
- 原有 CORE_A、使能掩码、回调及 owner 前后值。只有回调、owner、使能掩码和同请求校验均通过，才报告原厂 RSZ_OUT2 event15／WDMA2 event7 的 0→1 边沿。R10y 原厂掩码 0x401 未启用这两项；本版不启用中断、不写 ACK、不切换调试选择器。掩码关闭时不可用，不输出虚假的零耗时。
- 逐窗口保存 `/proc/PID/maps` 前后 CAP 映射、线程 start ticks 和原厂 pthread 身份。Que 的 VA 必须按本窗口稳定 `/dev/mem` 映射换算到 PA；不硬编码 R10y 的偏移。
- 通过 `/proc/PID/task/TID/syscall` 被动读取正在等待的系统调用。发现过程每 100ms 最多检查一个线程，缓存选中的只读文件；不附加调试器，不打开原厂编解码设备，不发送相机信号。系统调用读取不可用时记录阶段／errno，原有采样仍可继续。

## 原厂 HEVC 等待链独立核验

原厂 `libmmf-camcorder` 的 `waitHevcCallback`（modules+0x260b8）和编码完成回调（modules+0x25eb0）使用同一全局 semaphore（modules+0x5b0f8）。等待返回 PC 为 modules+0x260d0，上层 Encode 等待返回 PC 为 modules+0x2cc74。原厂 `libmmfosal` 的 cMmfSem 包装对象指向 80 字节 backing；counter 在 +0，条件变量在 +8。原厂 pthread 2.13 的等待 syscall PC 为 pthread+0xbd04，futex 地址为 backing+12。

四个独立原厂 ARM 回放覆盖构造布局、完整 modules→osal→pthread→FUTEX 链、原厂完成回调 Give、已有 token 时不等待。原厂 pthread 文件大小 84028，SHA256 `83aaaa614344f4d28047358eb7ce49665439bd7149bd17ad9fc1846a309abe9e`。解码器要求文件哈希和映射已核验、同一 backing 前后 counter 为负、精确 futex 地址和 PC、栈中两个原厂返回 PC、稳定系统调用对以及相同 Que 图像代际。普通 futex 或零散栈常量不算命中。

通过这些条件的连续向量给出“同图像原厂完成等待链的观测跨度”，包含固件、IRQ 和调度，不等同 HEVC 核心纯 busy，也不能证明两次采样之间始终阻塞。ioctl 观测只接受实际 HAL fd、请求号和参数指针；不执行 ioctl。

## 覆盖和预算

四文件导出不变，buffer-flow schema 2 仍为 1024 字节记录、1000 条容量，采集 RAM 文件仍为 18,560,000 字节，不增加 RTOS 内存。保留 100ms 环读取和同请求 completion-pending 最多两次补读；补读发现五元组变化只存头，不追踪新请求的对象或设备。

默认 5 秒一个窗口，每窗最多 80ms 墙钟／12ms CPU软预算，录像最多 26 个、前后取景各最多一个 16 向量窗口，目标间隔 2ms；接近下次环读取时让出。独立 stage CPU 账本按 10 秒检查，超过约 0.4% 降至 10／20 秒窗口。内存快照开销另计，不能把细窗口一起降频。预算是协作式边界，不能硬中断一个阻塞的内核读调用；实际时序由实机日志复核。

R10y 的 BM 表首址 0x81dfc908 非页对齐，以 4KiB 从首址读会每次跨页。现在先读 1784 字节至页边界，再按页读取，并用专用只读映射避免 32 页热缓存反复映射。25 秒超时和每次 0.5ms CPU软预算保留。根对象每秒核验一次，同时保留重读和完整快照书签；不再每次 100ms 都消耗快照预算。只对连续且全部在原白名单内的总线字批读，不扩大寄存器读取范围。

## 怎样进一步判断

分析结果分别输出原厂请求周期、同请求行变化区间、HEVC 同图像等待观测跨度、条件合格的 EOF 边沿、跨请求表面候选与 Que 元数据归还。请求头发布的 Linux 观测边界仅是区间参考；不直接相减 Linux 和 RTOS 的绝对时钟。十槽复用、跨 11 请求的同地址候选不会被误报为半秒交接延迟。Que tombstone 也不代表所有硬件消费者释放物理图像。

若实机获得稳定的尾行写入并明显早于完成，而同图像仍持续在原厂 HEVC 等待链，优先查 HEVC／返回调度；若写入持续至完成前，优先查 RSZ2／WDMA2 上游输出与并发关系。只有同时满足原厂路由和掩码的 EOF 才能进一步缩小这两者的边界。跨请求输出和编码重叠可检验缓冲并行是否存在，仍不能单凭重叠判定它导致延迟。

没有经过核实的 DDR 吞吐／仲裁停顿计数器可用。本包不启用未证实的调试寄存器；`DDR_contention_time_ms` 及各硬件精确 busy 时间保持空值。若仍缺有效边界，后续必须根据本次证据选择一个原厂阶段入口或一个隔离变量实验，不能保证此包一定把全部约 43ms 唯一分配给四项，更不能预先宣称能达到 30p。

## 本地验证的范围

新旧读取器和完整生产采集器均执行实际 ARM 指令；OS、DMA、MMIO、缓存可见性、调度和 CPU 成本为显式模型。历史 R10y 及更早实机文件仅用于解码回归。原厂等待链回放不证明相机内核允许 proc syscall 读取，也不证明真实 EOF 可见性。部署校验只证明 SD 文件一致，相机安装和硬件效果须在短测后检查最新安装日志、READY／DONE 和四文件。
