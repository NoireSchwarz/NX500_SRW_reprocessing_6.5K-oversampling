# R10t：注册对象类型与拒绝证据

R10s实测：稳定全宽录像104/104条各一次event10，owner均为0x8142f440，无重复/饱和/变化标记；route3无记录、拒绝9次。可比重快照多10次读取/88字节，与策略字段读取或其有效性检查附近退出一致；原值未保存，不能确认空指针。周期43.610ms，HW到最终IRQ43.123ms，回调到下一HW0.473ms，视频比音轨短1.0608秒。性能未修复。

## 原厂路径及生命周期

0x8142f1e8是84字节标量参数区；父对象0x8142e018的+FA0是某些分支选择的操作字段，原厂构造/准备/关闭路径会清空它。+FA4是View成员，+FA8是Still成员，+FAC是CS成员，不能混淆。View对象0x8142f434的主/通知类型为0x80582d10/0x80582d70；Still对象0x8142f450为0x80582da8/0x80582e08。原厂_setIntr和EnableInterrupt将this+12注册到event10 owner根0x8153cb28，原厂回调槽为0x817d8ae8，值0x801ca2f0。

R10s验证了选中分支的布局及空值拒绝规则，未证明整条实机录像路径一直填充FA0，也未保留失败原值。R10t直接读取已注册owner并受边界保护地检查owner-12主类型和owner通知类型，同时核对原厂View/Still成员。FA0仍独立保存；它的空值、变化或读取失败不再使View/Still对象证据消失。Base类型只有匹配FA0才关联；CS的通知成员布局仍不支持，不猜测。

## 数据和规则

route4仍占Linux头15552..16351，共800字节，不增加RTOS分配或改变counts记录ABI。头32字节后有4条192字节记录：前三条保存已核验快照，最后一条保存最近一次被拒绝快照；所有拒绝次数累计，较早拒绝记录覆盖情况明确报告。拒绝不消耗核验槽、不阻止之后重试；同一generation通过后去重，核验槽满则明确overflow。

记录包含前/后两组12个值：owner、回调、FA0、View、Still、LDC父类型/状态、IPC后端指针/类型/父类型、owner主/通知类型，以及读取掩码、变化掩码、timer标识/序号/哈希、采样mode/source、来源指针、期望后端和读取时长。读取失败值标为不可用，掩码区分实际0或0xffffffff。首个诊断问题与真正阻止关联的阶段分开保存。

正式对象关联要求：两次读数一致（可清空的FA0除外）、owner在RTOS RAM内且相同、精确支持的类型对、正确回调和父类型、canonical成员一致、LDC运行状态3、IPC后端及typed source/mode一致、producer9计时头稳定。停止/关闭状态、错类型、错误成员、owner变化或缺失关键读取只留下拒绝证据。阶段统计仍要求每帧单次有序命中、HW/IRQ无重复、owner匹配以及完整落在剔除两端各1秒的稳定来源区间。注册对象类型不等于选中操作、DMA缓冲身份、完整生命周期或纯硬件时间。

## 验证边界

原厂ARM执行Base/View/Still构造、原厂成员存储、注册及完整父层OTF准备/开始/停止/关闭/再开始控制流程，生成不同状态的对象字节交给生产ARM读取器。Still默认注册走bank1的owner槽0x8153cb78及0x801ca8c4回调，作为当前bank0观测的负例；不改动既有入口和0x801ca2f0要求。OTF硬件方法、分配、dynamic_cast结果和IRQ驱动端点仍为模型，未声称整机生命周期或硬件得到验证。验证覆盖空策略、可读但错误类型、未对齐/越界owner、关键读取失败、来源/计时变化、停止后遗留owner、拒绝留存及重试。R10r/R10s实测文件保留为负例，不追认类型关联。

RTOS producer9、0x804bb640/event10入口、原厂ACK/enable/mask、100ms环读取、三文件保存、全宽helper、蓝边/几何、UD初始化更新、码率/时钟/QoS均保持既有字节/行为。不重复码率试验，不恢复HEVC断点。实机通过关联后仍需继续拆分43ms长区间，尚无不可突破的硬件上限结论。
