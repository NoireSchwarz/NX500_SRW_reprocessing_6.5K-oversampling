# R10r：LDC EOF 中间观测短测

R10q 实测确认：全宽应用和保存成功，但 event7 未启用。R10r 使用同一原厂 EP_A 分发入口观察已经启用的 **event10／LDC EOF**，增加每帧命中次数、HW 时的 owner 与每次事件的 owner／回调检查，并核对当前 LDC 操作对象的类型。它是诊断版本，尚未证明提升帧率。

1. 安全弹出 SD，装入相机完成安装，随后**完整关机再开机、断开 USB**。补丁视频页应显示 **R10r LDC EOF OBSERVER**。必须重启清除 R10q 留在 RAM 中的旧观测代码；仅部署到 SD 不表示相机已运行新版。
2. 照片模式应用 **FULL WIDTH 4K 30P**，确认能正常返回。按提示在原厂菜单选择 NTSC、UHD30p、PRO，再回照片模式。沿用当前码率，BUS QOS A/B 保持默认。
3. 启动 **STAGE COUNTERS**，确认 **ON / STOP+SAVE**。退出补丁菜单进入视频取景，依次完成：**取景5秒 → 录像5秒 → 停录后等5秒**。
4. 回照片模式停止并保存，等到 **COUNTERS SAVED - SAFE TO CONNECT USB** 后再连接 USB。保留新安装日志、VIDEO_FULL_*、VIDEO_STAGE_* 和对应 MP4。
5. 先检查这段短测的 LDC 总命中、每帧次数、对象关联与两侧耗时，再决定下一步。此轮不需要长录像、全宽／裁切重复对照或码率切换。

若应用或采样报错，保留屏幕原文和发生步骤，恢复后回传 SD，避免连续重复触发。READY 表示就绪，DONE 表示三文件保存完成。

仍保存 counts.bin、frame-flow.bin、hevc-flow.bin。电脑分析入口为 **PC/R10R_LDC_OBSERVER/analyze_r10r.py**。缺失、同一帧多次命中、计数饱和、owner／回调变化、类型不匹配或跨模式边界，都保留为原始证据；只有单次、有序且对象关联通过的事件才统计阶段耗时。过渡帧通常不满足关联条件，不能把全段 LDC 覆盖为 false 直接解释成启动失败。

0～15 次为精确计数，16次及以上明确显示下界。尚未确认的操作对象类型只记录，不会冒充关联成功；同一 owner 也不能证明 Y/UV 缓冲身份。HEVC 断点继续停用。

本地验证使用真实 ARM 指令，部分 OS、缓存、时间和 MMIO 端点为模型，不能代替相机硬件结果。照片、录像、原始固件和历史日志保留，不清理或修复 SD。
