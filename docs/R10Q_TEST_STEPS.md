# R10q：核对 EP 中间观测点

R10p 实机已完成全宽→原生裁切→全宽应用及采样保存，但四份记录的 EP 总计数和逐帧命中均为零。本版修正观测入口及计时格式校验，并增加少量只读路由快照。它用于继续定位约 42.5ms 的 HW→最终 IRQ 区间，尚未证明提高帧率。

1. 安全弹出 SD，装入相机完成安装，随后**完整关机再开机，断开 USB**。确认补丁视频页显示 **R10q EP IRQ OBSERVER**。写到 SD 不等于相机已经安装；重启也用于清除 RAM 中旧版观测代码。
2. 照片模式应用一次 **FULL WIDTH 4K 30P**，确认能返回菜单、按键正常。按提示在原厂菜单选择 NTSC、UHD30p、PRO，再回照片模式。沿用当前码率；BUS QOS A/B 保持默认。
3. 启动 **STAGE COUNTERS**，确认 **ON / STOP+SAVE**，退出补丁菜单进入视频取景。先只录一段短测：**取景 5 秒 → 录像 5 秒 → 停录后等 5 秒**。
4. 回照片模式停止并保存计数，等到 **COUNTERS SAVED - SAFE TO CONNECT USB**，再连接 USB。
5. 保留新安装日志、VIDEO_FULL_*、VIDEO_STAGE_* 和对应 MP4。先检查这段短测的 EP 命中及路由证据，再决定是否需要长录像；本轮不再做码率对照，也不要求重复全宽／裁切／全宽三段测试。

如果应用或采样失败，保留报错原文和发生步骤，断电恢复后回传 SD；不要连续重复触发。READY 只表示采样器就绪，DONE 才表示保存完成；缺失计时、重复 EP、采样间隙和预算告警都会保留。

仍导出 counts.bin、frame-flow.bin、hevc-flow.bin 三个文件。新路由快照位于 counts.bin 现有头部，不增加每帧设备轮询；每个稳定视频状态只保存一次，最多六次，溢出明确标记。HEVC 断点继续停用。电脑分析入口为 PC/R10Q_EP_OBSERVER/analyze_r10q.py。

本地验证执行真实 ARM 指令和原厂调用路径，OS、缓存、时间与设备端点仍含模型。是否稳定、EP 事件是否在当前视频路径发生，以及帧率瓶颈位于中间点哪一侧，都需要这次相机记录确认。照片、录像、原始固件与历史日志不清理、不修复。
