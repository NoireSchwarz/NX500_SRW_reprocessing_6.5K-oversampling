# R10p：R10o 应用全宽卡死调查与修正

## 实机证据

用户报告：应用 FULL WIDTH 4K 30P 时直接卡死，断电重启恢复。SD 安装日志确认 recovery-r10o-ep-wdma2-observer 安装成功，内部模块清单 SHA-256 为 725df180785c32465865296fa57165c42ebb5e4868a5dae104a17b89470044a3。

最新失败目录 VIDEO_FULL_1794491299_445_c0fa4fc4 留下 native-before.txt 和 slot-preclean-order.txt，无完成结果或 native-retired.txt；一些文件在断电后读报 WinError 1392。它们保持原状，未修复或清理。缓冲日志缺失不能证明停在具体指令，也不能据读取错误直接认定文件系统是卡死根因。

## 确定的实现缺陷与可复现机制

R10o 把 0x804e1fbc..0x804e203b 当作可复用代码区，覆盖了原厂第二计时入口 0x804e1fec，以及 0x804e2020／0x804e2038。原厂 LCD 路径 0x803d0bc0、0x803d19f0 仍调用 0x804e1fec。

真实 P7 ARM 指令回放中，两条 LCD 路径在 R10o 补丁下均进入 0x804e200c，发生无效地址读取；恢复原厂 128 字节后均能继续。该结果证明实现缺陷及致故障路径，尚不能证明本次相机硬件卡死的精确 PC。旧测试从新观测入口执行，漏掉了原厂调用者，也没有覆盖原厂 marker 已执行 PUSH 后的安装交错。

另外，R10o 将 EP 时间写进原厂 TMC 开关字位置；如果只还原原厂尾部而保留该用法，会使原厂计时入口误认为计数功能已启用。因此不能只补一个 BX LR 或单独恢复代码尾部。

## 修正范围

- 该 128 字节整段保持原厂字节，作为只读指纹校验，不再写入或作代码区，也不对其额外执行代码缓存维护。
- 原厂 TMC 前五个控制字保持零；EP 计时和总回调计数放入已有实时头内，避免激活原厂计时功能。
- 观测缩回原先使用的 A/B 两区。保留 HW、EP 回调、final IRQ、IPC callback；暂时停用已知低优先级的 SRAM-load／CS0-start 计时，以腾出固定代码空间。
- producer schema 7 仍用 256 字节、8 槽、每槽 7 字：seq、HW、EP、EP 总计数、final IRQ、IPC callback、flags。flags 0x20 为 EP 命中，0x40 为两次或更多。计数随配置事务复位；窗口外回调只增加总计数，不能算作窗口内命中。
- fast 文件仍为 schema 2／312 字节、100ms 读取；不再读取原厂控制区作为新增数据。分析器兼容旧格式，暂停的观测计数输出 null／不可用，不能解释为测得零次。
- 在发布 RTOS 入口前和 RTOS 完成、UI 恢复后，保存并同步安装检查点。READY→GO 及停止 UI 的窗口内不加入 SD 同步操作，避免延长 RTOS 等待。

图像处理、UD init/update、全宽几何、蓝边修正、码率、时钟和 QoS 均未因此调整；HEVC 断点仍停用。

## 验证边界

新增回归在每个观测代码安装写入后执行两条真实原厂 LCD 路径；同时覆盖已经执行原厂 PUSH 的 marker 与安装交错、采样后三个原厂尾部入口、控制字保持零、原厂回调 ABI、配置回滚和三文件保存。R10o 的失败复现报告与相机失败证据另存，不以成功报告覆盖。

上述验证仍含 OS／缓存／计时外设模型，不能代替相机硬件复测。实机先只验证应用全宽能正常返回，再做 5 秒短测；暂不直接进行长录像。后续瓶颈判断继续以 HW→EP 与 EP→final IRQ 两段为主，重复码率测试不在本轮计划中。
