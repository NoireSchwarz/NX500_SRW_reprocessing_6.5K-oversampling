# R11a 检测器修正与证据范围

R10z 的实际证据是：安装并运行新版、全宽应用和四文件保存成功；四次内存快照均完成，录像期连续空闲98.171875MiB；bit6→bit2约42.900249ms，完成至下一请求约0.480796ms。10个细窗口全在第一条阶段记录前超预算，故没有新的WDMA2行变化或HEVC等待链证据。相机maps有851–876行，旧解析器上限512行；20个映射记录均为失败状态。现有证据不足以选择硬件阶段直接修改，R11a属于检测包。

R11a保留RTOS producer11、event10、bit6、首末输入绑定、全宽helper和原厂配置。仅重建Linux采集器及菜单，不改时钟、QoS、码率、IRQ使能、ACK或调试选择器，不调用编解码设备，不写图像，不附加调试器。

完整maps扫描移到冷任务：每个100ms周期最多一次4096字节顺序读取，最多处理4096字节／32行；CPU软预算0.8ms、墙钟软预算3ms，时钟检查按256字节批次进行。单个内核read不可被软预算打断，所以仍会记录真实延迟和环覆盖。总边界为256KiB、4096行、15秒，超出明确失败，不能截断后当作完整。保留线程／进程生存期、完整CAP映射、原厂pthread身份以及失败阶段、errno、字节与行数、扫描epoch和起止时间。

扫描完成后才进入热窗口，第一条实际阶段向量先于可选CImage／旧Que快照。热窗口仍最多80ms、12ms CPU、录像最多26条／取景最多16条，目标间隔2ms，优先让出下次100ms环读取。旧Que的归还补读安排在随后一个周期，并要求原生请求仍有推进；结束映射扫描再分步执行，不再在热窗口末尾同步扫描。停止、USB或上下文变化时，只关闭自己的proc文件并在RAM标记中止，绝不为了补书签重新读取设备或写SD。

格式3显式保存两次完整扫描的实际时间区间。分析器仅在完整CAP映射相同、前扫描结束至首向量不超过500ms、后扫描开始在末向量之后且不超过500ms、epoch递增、扫描不超过16秒解释容差、扫描结束早于其发布记录时接受区间包围关系。扫描不是瞬时硬件锁存，也无法排除未观测的映射ABA。完整失败或不及时的扫描使缓冲／等待关联不可用，原始阶段向量仍保留。

maps和线程发现单独记CPU账，不再消耗热窗口首条记录预算；总观察CPU仍在头和总进程账本中保留。疑似FUTEX和实际HAL调用候选保留失败证明，而非只保留每16项。发现间隔继续错开相位，每周期最多检查一个线程。原厂等待链认证没有放宽：库文件哈希、映射、精确futex地址／PC、两个原厂返回PC、负counter、稳定系统调用对、线程start ticks、同请求及同图像代际均须成立。

四个导出文件及18,560,000字节RAM数据文件保持不变。Linux小型扫描／上下文状态另计，原厂ARM编译检查将两个观察上下文的合计限制在8192字节内；不申请RTOS或CAP内存。原厂EOF掩码关闭时继续标记不可用。行指纹变化只圈定可见写入，不证明整帧EOF或唯一写入者；原厂完成等待包含固件、IRQ及调度，不能当作HEVC纯硬件busy。没有经过核实的DDR争用计数器，精确DDR时间保持空值。

验证包括本次真实851行maps、pthread超出512行、慢读取、截断、过长、权限／读失败、PID重用、重复pthread、CAP容量、字节／时间边界，以及完整生产ARM合并流程。OS、DMA、缓存、调度和CPU成本仍为模型；历史实机仅用于回归。本包部署校验不等于相机已安装或实机性能已验证。
