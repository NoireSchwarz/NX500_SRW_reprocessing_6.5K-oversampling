# R10v：原厂接受的 IPC bit6 与跨视角请求原值

R10u 实测确认内部安装、全宽应用、开始及停止保存成功。稳定录像183请求各一次event10，原生首末输入绑定183/183通过；周期43.180315ms，HW→IRQ42.701453ms，IRQ→成功通知0.010771ms。独立Linux上下文关联123/183，精确请求快照6个。sample59/request333中，RTOS当前输入8278d800/PA a4b40000与RDMA0一致，Linux父对象却读到上一请求332的8278f800/PA aa7c8900。缓存可见性与短暂对象复用仍待区分。

## 原厂依据与核验范围

P7 SHA256 `f8e417cb5b55768851ba7e2b8017d3a98dc0b0c8444cc0a5061265cc08dbbf7f`。原厂QHD注册函数801cf290将ID46连接到801cdf4c，后者向IPC父对象发事件4，经801cdc84继续通知。R10u读取的IRQ44 enable=cc包含bit6，但没有保存实际slot6，所以本轮交付前仍无法从旧SD证据证明实机回调及每请求命中。

观测放在原厂IRQ44的bank2已接受分支80036c00，执行原LSL后、原ACK之前。仅处理index2/6；原厂从813f09b4表派发。每次bit6从原厂本次调用所用的R7表读取slot6，并检查是否801cdf4c。独立Linux双读813f09cc和20810468保存实际回调、使能原值与读取掩码。没有打开新的中断，没有改变ACK/回调/EOI。

原R10u IRQ入口80036aec恢复原厂字节；最终IRQ时间现在是接受的bank2 bit2时刻，因此不是同一个微秒级基准。event10入口804bb644保持原有status/mask/ACK及owner判定。成功通知801cdc40继续首末输入绑定、关窗和发布，不再保存该通知的时间。

bit2与bit6若同次挂起，原厂可能先分发bit2并成功关窗，再分发bit6；后者只增加全局计数。不能将这种窗口外事件硬配给刚发布的请求，也不修改已提交环记录。首个bit6只有单次、时序在HW与bit2之间、原生回调符合且有独立类型/slot6上下文时，才产生两段统计。它仍不是已经证明的硬件EOF、DMA退役或HEVC完成。

## 固定边界及格式

ARM/Thumb2观察体继续限于A608/B236字节，保留所有原厂BX入口、804e1fbc..203b的128字节尾部、后续独立TMC记录器和TMC前五个零控制字。没有新增RTOS分配；原临时CAP退役/归还流程、几何蓝边、UD/QHD配方、码率、时钟、QoS、采样入口shell保持。

producer11/magic42544c56，数据256字节、总租用280字节；16字头、4×12字记录、100ms快读、完整26MHz tick。每条：seq、flags、LDC累计、HW、接受bit2、首次event10、HW时owner、输入描述符、输入PA、输出描述符、首次bit6、最近绑定失败原值。

flags：低0..14位的请求/HW/IRQ/成功/取消、LDC有无及饱和/owner变化、IRQ重复、首末绑定及四种绑定错误沿用。bit16为HW重复下界；bit17表示任一次bit6实际回调不符。LDC精确0..15计数改为bits20..23，bit6计数bits28..31为精确0..14、15表示15次或更多；controller仍bits24..25。没有把饱和下界报告为精确次数。重复/取消/未关联事件保留原记录。

头14保存当前请求最近一次bit6实际回调（新请求清零），头15是全局已接受bit6计数，包含窗口外事件并按32位回绕。原成功时间字段改为首次bit6时间；解码明确标记completion_timestamp_available=false，不套用旧尾部时间指标。

## RTOS／Linux同请求原值

Linux记录1280字节、头16384字节和RAM容量保持。ep_readback128字节升级为NXL_IPC_LINK2；原progress128字节改为前后各16字RTOS头，使用新valid bit4194304并清除旧progress标记。本版停止重复采集旧稀疏IPC/EP状态向量；原有completion状态快照仍保留，旧文件解码兼容。

独立向量双读父类型/状态、活动后端、driver/preset、输入描述符/类型/PA、RDMA0配置、输出描述符/类型；另外双读slot6实际回调和使能，保存每次读的原值、掩码和时间跨度。失败的RTOS头整份标记FFFFFFFF，不能留下部分成功值伪装完整读取。

前后16字头完全一致、处于同一活动HW请求，才能认定是同一pending序号。输入/PA/输出tuple与Linux不符时保留两侧原值并明确排除，不能通过放宽检查或写缓存使其“通过”。slot6核验与地址一致性分别报告，允许一次地址差异仍保留可靠的回调原值。稳定类型上下文只是候选关联；精确同请求匹配另外计数；硬件锁存图像/HEVC身份仍为false。

## 验证与后续

使用真实ARM/Thumb2和原厂请求更新、DMA编程、完整IRQ/EP/成功通知/客户派发，对照寄存器、栈、CPSR、原厂ACK/EOI。测试bit6空/错误/恢复回调、0/1/多次/饱和、HW前、窗口外、同次bit2+bit6、计数/时钟/环回绕、输入类型/指针/PA变化、每个安装写入的真实LCD入口。单独测试真实ARM双读原值、部分读失败、同前缀不同RTOS tuple及跨视角差异、解码拒绝、实际采集器启动/保存失败恢复、旧相机记录兼容。

OS、设备时钟、缓存、MMIO及部分调用端点仍是模型；验证通过不能证明实机不会卡死或帧率已改善。真实slot6、每请求命中和区间拆分以本次包安装并完整断电后的相机短测为准。

下一轮只按R10V_TEST_STEPS做全宽短测。若bit6单次且有效，比较HW→bit6、bit6→接受bit2；若缺失/多次/回调不符/窗外，则报告不能拆分。结合两侧地址原值继续区分缓存可见性、临时复用与真实管线变化，不重复码率测试。
