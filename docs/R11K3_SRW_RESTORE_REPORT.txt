R11k3 重显影恢复包 / 2026-11-18 Europe/Berlin

本轮目标是恢复原有 SRW 重显影，撤回新增曲线诊断模式。曲线拟合、颜色矩阵、LUT 仿真及 A/B/A 分析移到电脑端；项目根目录 AGENTS.md 已记录这条开发原则。

已确认的失败链：
1. R11k 新增曲线诊断预设、schema2、前端/RTOS固定曲线与第四份证据文件。--version首行被错误插入新标签，触发原有生产校验拒绝；R11k1修正首行。
2. R11k1实机完成原生ISP帧，随后在Linux工作区交接时误用16KB虚拟地址对齐规则；原厂返回的VA为4KB页对齐。R11k2修复三处消费者，物理地址仍16KB。
3. R11k2已实际安装；新任务在原生调用前因Bank2最大连续180MiB不足192MiB退出。原分配表有六块非本任务分配，空闲区分别180和20.875MiB。不能仅凭类型编号认定这些缓冲的原厂用途。
4. 最新两次退出为EP_DEVICE_FD_IN_USE，具体进程811、/usr/bin/sap-server-1.0.0、/proc/811/fd/42。两次均尚未获得EP引用，原生调用数0。固件找到原厂sap.service。
5. Bank2申请路径、192MiB容量及EP他进程检查在诊断修改前已存在。没有证据证明Gamma诊断直接造成原厂内存和SAP占用；此前测试未覆盖这些运行状态。

本包恢复和修正：
- 原版SRW菜单及三个Gamma选项恢复；前端控制、Gamma协议、Gamma宿主和RTOS源码回到R11j存档。新增LINEAR/LOG TRANSFER诊断入口、schema2和第四份强制保存要求撤回。
- 保留VA4KB/PA16KB校验修正与工作区逐阶段失败日志。
- RAW输入、ISP输出起点、6480x4320尺寸、6496 stride均不变。工作区192→176MiB，后段LDC输出128→120MiB。ISP输出尾117.5752MiB，LDC输出尾173.5752MiB，表区起175.875MiB，各活跃图像及保护区分离。前端128MiB缓存窗口保留；LDC只在已确认前端回调与控制入口退休后运行。
- 新旧160/192MiB已完成回执仍可读取；当前176MiB任务继续做全范围所有权及归还检查，不允许强制释放未知缓冲。
- 容量不足时仍拒绝提交，并将该次分配表复制到SD失败目录。
- 自动显影前仅对经原厂unit和可执行文件SHA验证、MainPID稳定且确有EP描述符的sap.service请求原厂停止。确认旧进程退出后，仍执行原有EP准入检查。完整任务结束后由原厂启动服务；早期退出和中断执行同一恢复。原生状态未知时保留停止状态及所有权记录，不强行恢复或重置硬件。手机附件连接会在该显影事务期间暂停。
- 视频Log、全宽24p、核心库及原有EP检查程序字节不变。

验证：四份实机分配表在旧版均拒绝192MiB、恢复版均允许176MiB；低于176MiB仍拒绝。56组真实ARM消费者场景、409条契约断言、12组实际导出函数、原版Gamma/LDC状态机、生产分辨率DMA布局、11组服务生命周期及2组真实退出/信号清理流程通过。生产shell版本校验8组及R11k2接续完整模块安装通过。RTOS二进制与诊断前存档同长65324字节，仅容量常量对应的两个字节变化。

范围限制：以上在电脑端执行真实ARM指令或生产shell，OS、原生调用、设备、DMA和IRQ端点按报告建模。服务manager和进程视图也在夹具中模拟。这不是本包已在相机运行、ISP硬件已验收或最终JPEG像素正确的证明。下一次只验收一张原有SOURCE19显影，不安排新的诊断组合。
