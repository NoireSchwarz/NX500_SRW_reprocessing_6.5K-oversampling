# R10x 观测预算、覆盖与 RSZ2／WDMA2—HEVC 地址关联

R10w 实机安装和全宽应用成功，但观测未拆开内部耗时。稳定1335请求的bit6、event10各一次，首末输入绑定全部通过；bit6→bit2平均43.076815ms、完整周期43.589242ms。31.4004秒时全局CPU预算把phase改成VP_FULL，后续密集窗口停止，快读和重快照却继续。一次环读守卫拒绝造成追踪序号255缺失；唯一原始完成pending跨请求535→536，正确拒绝关联。不能拿这些记录宣布DDR、编码器或IRQ等待已确定为根因。

本版先纠正观测器，再补实际输出配置和HEVC提交地址的只读证据。不改变全宽几何、码率、QoS、时钟或图像处理路径，不重复码率测试。

## 不变的部分

R10v起已实测的RTOS代码、event10、bit6、首末CImage/PA/RDMA0绑定、producer11、280字节租约和全宽helper逐字节保持。RTOS SHA256为`bca928cd373590bf0386efb2bbe06b0b98f99c82f907f01fd9a89c0d9c4cb2a7`，helper为`4839e68c0b96fb0a627259e5c74da047e9e44dea183108ad805b17e80d81ea2c`。没有新增相机端入口、IRQ使能、ACK、缓存操作、目标函数调用、堆或图像分配。HEVC断点、fork和ptrace继续停用。

## 预算与覆盖

快读、重快照和输出/密集观测分别累计实际进程CPU时间，每10秒保存独立账本。重快照目标0.3%，超过目标时200→500→1000→2000→5000ms退让；快读目标0.2%，只记录超限，不静默改变100ms期限；输出/密集观测目标0.1%，超过目标时窗口间隔5→10→20秒、周期快照1→2→5秒退让。每个密集窗口仍有4ms CPU、60ms墙钟、下一次快读前5ms预留和最多24次请求2ms间隔读取。预算只限制下一次观测，不能中断阻塞中的内核读取；实际间隔、CPU、容量和deadline仍需检查。

CPU退让不设置VP_FULL，也不直接把快读覆盖判成失败。真实容量、守卫拒绝、序号缺口和过长间隔分别报告。重快照容量耗尽也不连带禁止快读/阶段观测。

快读格式4仍用312字节记录、12000条容量。第一次头/模式不一致且识别到原生计时器时，在距首次开始2ms以内至多重读一次。首次拒绝原样提交为标记记录，重读结果单独提交，解码核对成对关系、重读账本与整个128字节头哈希。恢复可用不能抹去首次失败；重读仍失败或实际追踪有缺口时不会报告完整覆盖。缺失计时器不反复重读。

## 原厂只读依据

固定P7 SHA256：`f8e417cb5b55768851ba7e2b8017d3a98dc0b0c8444cc0a5061265cc08dbbf7f`。

* `_udd_ep_mux_rsz_wdxi_2`的804b99d0..99e8把2082110c或2082120c的bits8..11设为7，配置RSZ2→WDMA2；它不是忙计数器。
* WDMA setter 804b6b98使用20821700+通道×100+CS×80；804b6c4c把步幅放进bits12..30。R10w录像中WDMA2 bank0的Y/UV为b3b50000/b4339000、步幅3840、UV-Y=3840×2160。R10x重复读两个bank的五个配置字，保留当前实际布局及变化，不把地址稳定称为退役。
* D0/D4/D8由原厂EP中断分发读取，ACK另在58/5c/60。保留原始状态和软件mask，不启用中断、不清状态、不擅自给未核实位编号赋模块完成含义。原生RSZ中断计数81459970/74与bit3/7实际回调槽也仅作为旁证。
* E0只在原厂已选B0=2、前后仍为2时读取，不写选择器；不把其未经证实的位解释为NX500逐阶段忙时间。
* 相机原厂`libmmfmodules.so`整库哈希为`e40d3c7fdbab8ea7f67d0e876468c2a31fa8572d602d969d32348f3fd0f45de7`。`cHalHevcVideoEncoder::Encode`在2cbc8/2cbd0读YUV+2c/+34，在2cbd8取HAL+108描述符，在2cbe0/2cbe8写描述符+8/+c；2ccf8在取回结果之后递增HAL+174。HAL+11c只是提交参数，不能当busy。

启动额外核对RSZ2 mux和WDMA stride原厂指纹；库身份仍核对完整三库哈希和实际加载基址。未知/部分版本拒绝启动，不尝试修复固件。

## 输出与HEVC关联

只有已验证的活动原生请求才读新增MMIO。录像源必须是受支持的相机/源类型；两个全16字RTOS头、模式、RDMA0输入、输出CImage类型/PA、WDMA2配置、Linux HAL类型/根/提交描述符/结果计数和源状态分别有独立守卫和读取掩码。部分读取保留原始值，不能参与匹配。

分别报告WDMA2与HEVC的Y/UV地址一致、输出CImage的Y与WDMA2一致、三方地址一致，以及原生首末绑定是否精确命中。周期快照和密集向量都追加保留，录像的地址证据不会被最后的预览覆盖。

地址相等仍可能是缓冲复用；HAL提交描述符也可能保留上一帧。结果计数推进只证明快照间走过取结果后的返回路径；原厂这段代码没有独立保存结果ioctl的返回状态，所以不能把计数直接当成功编码或缓冲归还，尚不能把它归为某一个同地址缓冲的归还。解码始终把精确跨域帧身份、HEVC同缓冲归还和硬件忙耗时标为未证明，不由地址匹配自动推导下游反压。保留当前event10和bit6服务时间；不把Linux纳秒减RTOS tick。

本版没有找到可直接作为RSZ2独立完成计时器的原厂只读接口。`d5_ep_top_cs_ready`实际执行配置写入，不能调用来“查询”。当前有效新增观测是实际输出布局、原生对象地址与HEVC提交描述符的关联，以及原始状态/结果推进；不声称已经拆出LCAC、NR或缩放各自耗时。仍未使能的EOF通知不是“模块不工作”。

## 导出与验证

三文件保存流程保留。第三文件`hevc-flow.bin`现在为NXL_PIPELINE2：128字节头、600×512字节记录；复用停用HEVC区，总采集器RAM仍11760512字节，没有新增RTOS分配。每窗口最多24个向量和4个路由快照，另有周期快照/预算记录；实际容量用尽明确标记，不覆盖旧记录。约90秒以内的一次合并测试可保留足够窗口；异常或容量标记不等于录像丢帧。

使用`PC/R10X_OUTPUT_BUFFER_LINK/analyze_r10x.py`，旧R10w及更早三文件继续兼容。验证包括真实ARM读取器与完整采集器、独立持续预算过载、有限重读、跨请求/复用/地址变化/部分读取拒绝、菜单启停保存、USB退出后RAM保存恢复、原厂指令和历史实机回归。OS、时钟、MMIO和缓存仍有模型，不能替代实机安全性或吞吐验证。
