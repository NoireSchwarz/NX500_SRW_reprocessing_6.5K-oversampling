# R11d：并行访存的受控对照包

R11c 实机确认：录像普通周期约42.162ms，bit6→bit2平均42.698ms；4个请求在HEVC取结果路径计数前进后，底行中部仍晚2–11.2ms出现可见变化。旧的RSZ2／WDMA2 EOF路由没有合格命中，继续密集读取同一零值标记不能区分处理耗时和共享访存影响。本包转为有撤回和CPU对照的工作集干预实验，不是帧率修复。

## 这次回答的问题

在同一段全宽录像中，增加采集器自己的大工作集读取，是否使bit6→bit2比相近CPU占用的小工作集条件更慢；剂量提高是否增加延迟；撤去后能否恢复。

每4个6秒区段组成一组，四种条件各出现一次，共8组／32段、192秒。采用随本次采样cookie选择的平衡顺序，避免总把某条件放在开头或结尾。每段前2秒和末300ms不纳入稳定帧比较。

| 条件 | 每100ms的CPU时间目标 | 读取的私有工作集 |
|---|---:|---|
| 空载 | 0ms额外负载 | 无 |
| 小工作集对照 | 20ms | 反复读取4KiB |
| 较低大工作集剂量 | 20ms合计 | 前约5ms读8MiB区域，其余读4KiB |
| 较高大工作集剂量 | 20ms | 读8MiB区域 |

两档大工作集和小工作集使用同一个ARM LDM8读取内核；只改变地址掩码和分配CPU时间。每批64KiB，逐批检查CPU／墙钟／停止条件；30ms为墙钟软上限，另保留下一100ms快读的让出余量。20ms是目标而非实机硬上限，分析使用记录的实际CPU时间和读取量。不会靠假定“配置了20ms”认定条件已匹配。

## 资源和生命周期

- 私有匿名Linux内存8MiB，另有两页虚拟守卫；不申请RTOS／CAP图像内存，不读取相机图像作负载。初始化后数据区设为只读，两侧设为不可访问。采样数据RAM文件仍为18,560,000字节；新增私有数据驻留上限8MiB，原stage两个上下文与新增实验状态合计验证不超过16KiB；既有缓冲表、页缓存和临时栈另计。
- 初始化要求Linux MemFree至少24MiB，预分配后至少16MiB；运行检查低于8MiB或无法取得有效MemFree时中止实验，释放私有区。资源不足时仍可保存普通采样和明确的不可用原因，菜单显示TEST UNAVAILABLE。
- 仅在已识别的NTSC UHD流程、schema11原生环、录像source稳定10秒后开始一次。每次负载前重新核对当前camera／source／HAL根、类型和录像状态；记录失败时的原始身份。对象／模式变更后终止，不重新开始或沿用旧指针。
- 独立每秒读取CPU0频率／governor、DDR A getter的两次一致性状态、MemFree；不跟随旧重快照的自适应退让。每条负载记录保留缓存年龄，超过1.5秒不作为合格配对数据。DDR getter第二返回值是双读状态，绝不标为另一个DDR通道频率。
- 停止、USB和进程退出时先停止实验并释放本进程分配，再走既有RAM保留／四文件保存流程。没有线程、fork、ptrace、相机信号、设备写入、ACK、IRQ使能、QOS／时钟／debug selector修改或原厂目标函数调用。
- 预览期可保留旧严格锚点。录像准备期和实验开始后的全部条件及恢复期统一暂停旧密集行探针／冷扫描；CAP分配表扫描在本包所有条件中都停用。R11c录像早／晚分配表继续作为历史证据，避免把约22秒扫描与某个条件绑定。
- 现有RTOS入口、event10、bit6、首末输入绑定、全宽helper及21项保护路径逐字节不变。采样不自动应用全宽；按测试说明手动应用并核验版本。

## 数据和判定

buffer-flow升级为schema6，仍1024字节记录、1000条上限、四文件导出。kind10为准入／开始／区段／结束／中止／最终元数据；kind11每条封装最多10个96字节负载明细。容器时间是提交时间，明细保留真实起止时间，不把一秒汇总当作瞬时读数。

保留实际大／小逻辑读取字节、CPU和墙钟、大工作集读取结束窗口及CPU量、原生完成序号前后值、频率及遥测年龄。逻辑加载字节不是DDR总线流量。只读保存系统暴露的Data／Unified缓存清单，以及可用时私有区的pagemap PFN摘要；这些不证明完整缓存拓扑或物理DDR通道。

原生周期和bit6→bit2持续使用RTOS时钟计算；条件分组使用相邻两帧完整Linux发布区间，保留2秒稳定期和300ms尾部守卫。没有Linux绝对时间减RTOS绝对tick，也不宣称已取得精确逐帧负载重叠时间。保留每帧原始序号，可按mod10等权汇总，避免每十帧尖峰分布影响区段比较。

每组同时检查有效帧、负载执行覆盖、实际CPU占用、频率／governor、DDR A双读状态、数据年龄和高低剂量分离。8组均合格后报告配对差值；以实验组为统计单位，不把数千帧伪装成独立重复。符号翻转p值只作残差符号对称假设下的描述性支持，不是精确随机化证明。还单列撤去大工作集的转换，以及实验结束5秒后的同一录像空载恢复段。

判读：
1. 大工作集比小工作集更慢、两档呈剂量趋势、8组方向一致且撤去后恢复：支持“大工作集访存会影响这条录像路径”，优先查共享缓存／互连／内存控制器交互。
2. 小工作集与大工作集都相近变慢：优先考虑CPU占用／调度影响，不能只归DDR。
3. 有效覆盖和剂量下没有额外变化：只说明在本次压力和地址位置下未见影响，不能排除其他DDR通道、主设备或更高压力。
4. 时钟变化、负载未执行、类型／覆盖不足、无法恢复：明确标为不完整或有混杂，不输出“没有瓶颈”。

即使得到阳性结果，也不证明原有约8.8ms差额全部来自HEVC的DDR争用。RSZ2／WDMA2独立忙时长、DDR真实流量／stall、图像物理归还保持未知。后续根据实际差值选择单项实验，不再默认追加同一批零值EOF观察。

## 验证边界

真实生产ARM的LDM读取、平衡调度、停止／保护／生命周期和四文件保存进入验证；原HEVC联合判定、白名单、映射、菜单协议及历代相机数据回归保留。75份R11c原解码文件按实机发布源码哈希冻结在测试目录，部署后也不会把当前新解码器当作旧基准。OS、缓存、DMA、调度、频率和内存位置仍有模拟。包内通过不等于相机已安装、实机不会卡死或帧率修复成功。
