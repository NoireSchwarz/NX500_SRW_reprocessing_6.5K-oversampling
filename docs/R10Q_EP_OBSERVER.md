# R10q：EP 入口与计时格式校验修正

## 现有实机证据

R10p 安装日志确认 recovery-r10p-native-tail-safe-ep，模块清单 SHA-256 为 5b80029d673ae019c9957c877d4520d25b048e5030d47d8ecbdf6ec42ecdf7ea。全宽→原生裁切→全宽三次配置均正常退休，四段采样均有 READY、DONE 与完整三文件。四段 EP 总计数与逐帧命中均为零，不能从其中拆出 EP 两侧耗时。

相同录像设置的稳定区间：两段全宽普通帧周期约 43.018／42.984ms，HW→最终 IRQ 约 42.532／42.504ms；原生裁切周期约 33.364ms。两次全宽结果一致。全宽新增帧率约 23.26fps，另有补帧；保存 MP4 的画面时长短于音频。阶段计时缺失不是码率瓶颈证据，不重复已经没有明显变化的 100／80／70 码率测试。

## 入口问题及修正

R10p 观测位置 0x801cab38 属于上层回调 0x801cab24，依赖 owner 0x8153cb98 非空。原厂 EP_A 分发器 0x804bb5f0 经软件掩码和原生状态检查后，可以调用不同回调或空回调；原厂其他路径确实也为 bank0 port7 注册过 0x8013c370。因此，上层入口不能代表所有 EP event7。这是静态可证实的设计缺口；当前视频实际选了哪个回调、硬件是否产生该事件，R10p 日志不足以确认。

R10q 将唯一 EP 观测点移至 **0x804bb640**：原厂检查 status & mask & (1<<index) 命中以后、原厂 ACK 写入以前。只统计 **bank0 event7（WDXI2 EOF）**。恢复所有保存的寄存器和 CPSR 后执行被替换的 `ldr r3,[sp]`，继续 0x804bb644；原厂 ACK、回调表、回调和 EOI 照常执行。不启用中断，不改掩码，不在补丁中写 ACK，不依赖上层 owner 或回调存在。

0x801cab38..0x801cab3f 恢复为原厂字节并作为不可变指纹；已部署 R10p 的旧 RAM 会被拒绝，要求完整重启。继续保留 R10p 恢复的 OEM 尾部 0x804e1fbc..0x804e203b 和前五个 TMC 控制字为零。只使用原有 A608／B236 字节，TMC 租用仍为 280 字节，八槽，没有新增 RTOS 分配。全宽图像几何、UD init/update、缩放、蓝边处理、码率、时钟和 QoS 不变。

Producer **schema8 / magic0x38544c56**：实时头与八槽布局同 schema7；EP 字段现在表示原厂分发器接受的 event7。flags0x20 表示当前 HW→IPC 回调窗口首次命中，0x40 表示多次。总事件计数包含窗口外命中。缺失、重复或顺序不符均不能算有效拆分，事件与当前 IPC 窗口的关联仍不证明 Y/UV 缓冲身份或 HEVC 归还。

## 计时校验与路由证据

完成状态、硬件进度、EP 辅助读回三个入口原先仍把新格式当作旧格式4校验。现统一精确检查 magic/version：4／6／7／8 共用八字头，格式5只允许自己的布局，未知或错配版本拒绝。采样器的慢速和100ms读取也共用版本识别。完成状态按 sequence/HW 判断同一请求，不再把 schema7／8 的 EP 总计数解释为起始时间。分析器支持 schema8，保留旧文件兼容性。

新增 NXL_EP_ROUTE1 位于 counts.bin 原有16KiB头的 15552..16351，六条128字节快照加32字节头；不改变文件大小或三个输出文件。已有视频状态稳定2秒后每个 generation 保存一次。两次读取软件 mask、硬件 enable、bank0 port5..9 回调、bank1 port7 回调、两个上层 owner、旧／新入口指令；前后相同计时头与模式／source／类型复核成功才提交。已有 IRQ_A／B／DMA 总数只转存早先计数快照。失败可重试，容量溢出明确记录。只读地址有严格白名单；从不读 ACK、共享高低计时器或改变调试选择。

快照能区分“目标事件未启用”“不同或空回调”“指令字节不符”等候选条件；它不证明事件真正触发，也不证明 I-cache 可见性。若 event7 总计数增加但逐帧命中缺失，应检查事件是否位于当前 HW 窗口外；若有单次有序命中，才比较 HW→EP IRQ 和 EP IRQ→最终 IRQ。若总计数仍零，应结合快照和 IRQ 增量先确认路由／可见性，不盲目启用其他中断或直接改图像管线。

## 验证边界

回放整个原厂 EP_A 分发器并比较寄存器、CPSR、ACK 顺序、回调次数和 EOI；覆盖空／其他回调、屏蔽／未发生事件、其他端口、bank1、事件重复及时间顺序。每次安装写入后还运行两条原厂 LCD 路径和原厂 EP_A 路径。事务故障、旧 RAM 指纹、100ms采集、三文件保存、重试与菜单协议继续回归。

真实 ARM 编译的生产读取器覆盖4／6／7／8格式、格式5隔离、错误版本／magic、请求变化、有限完成状态追踪、只读路由地址、模式／类型／source变化、重复 generation、六槽溢出，以及 Python 解码校验。R10n／R10p 已存实机文件另做兼容检查。以上包含模拟 OS、缓存和 MMIO 端点，不能代替相机硬件结果，也不证明30p已达成。
