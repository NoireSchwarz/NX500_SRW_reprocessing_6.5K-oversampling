# R10y 内存与缓冲交接合并测试

本包修正观测，不宣称已修复全宽帧率。只做下面一段全宽测试，不再加原生4K、码率或QoS对照。

1. 将部署好的SD卡装入相机，等待安装完成。完整关机，取出电池约10秒后重新开机；测试时断开USB。
2. 补丁视频页应显示 `R10y BUFFER LIFETIME`。采集器应为 `R10y BUFFER_LIFETIME`；全宽helper、RTOS producer11和现有event10/bit6仍沿用前版，这是预期。
3. 在照片模式应用 `FULL WIDTH 4K 30P`。按提示在原厂菜单重新选择NTSC、UHD30p、PRO，然后回到照片模式。BUS QOS保持默认。
4. 开启 `STAGE COUNTERS`，确认显示 `ON / STOP+SAVE`。保持照片模式5秒，确认菜单、按键仍可操作。
5. 退出补丁菜单，进入视频取景：**取景30秒 → 录像90秒 → 停录后继续取景30秒**。尽量保持固定机位、焦距、曝光、白平衡和对焦，不切换模式或其它补丁设置。
6. 回照片模式，再按 `STAGE COUNTERS` 停止并保存。等待明确显示 **`COUNTERS SAVED - SAFE TO CONNECT USB`** 后，再连接USB。保存期间不要关机或拔卡。

本轮增加了稀疏分批内存快照，前后各30秒取景用于覆盖快照；不需要另做5秒独立采样，也不需要第二段录像。测试约3分钟即可。

请保留新安装日志、对应 `VIDEO_FULL_*`、`VIDEO_STAGE_*` 和完整MP4。`VIDEO_STAGE_*` 现在应有：

- `READY`、`DONE`
- `counts.bin`
- `frame-flow.bin`
- `hevc-flow.bin`（HEVC断点仍停用，保留原有只读快照）
- **`buffer-flow.bin`（本版新增，包含跨请求记录、类型/地址和内存快照）**

四个bin全部成功导出后才会发布DONE和保存成功。文件不完整、提示保存失败时，保留原目录和提示信息；不要删除已有文件或清理旧日志。

本轮核对顺序：实际安装与运行版本 → 100ms环覆盖 → 四阶段内存快照是否完成/一致 → 原厂Buffer类型和地址域 → MMF槽状态与跨请求WDMA2/HEVC地址候选 → 完成pending的同请求有限补读 → 稳定录像计时和成片音画时长。

快照可能因正在变更、读失败、预算或模式切换而不可用，这些会明确记录，不算成零占用或已证明空闲。两次相同的Linux可见分配表仍不自动证明RTOS缓存已发布；元数据槽归还也不自动证明物理图像已经释放。

若应用全宽或开始采样立即报错、卡死，不要继续录制；记录发生在哪一步及屏幕原文，保留日志。断电恢复不会把未完成采样变成成功记录。

本包不更改当前RTOS入口、event10、bit6、首末绑定、全宽几何、蓝边修复、码率、时钟或QoS；不运行格式化、修复、清理及历史源码生成脚本。
