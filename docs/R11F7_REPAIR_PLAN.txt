R11f7 激活交接、进程识别与 R11f6 状态接续修复说明

已确认的故障链
R11f6 相机记录证明 157285888 字节完整备份已完成并复核。流程到 REQUEST_RECOVERY 后记录 Terminated，旧入口把 REFRESH_REQUESTED 改成 FAILED；旧预加载脚本遇到 FAILED 直接退出。真实 shell 信号回放复现了这一状态污染。原固件 systemd 208 的 rescue 使用隔离事务，可能终止发起方；相机日志没有记录具体信号发送者，不能把这一点说成已实机证明。
原固件标准 PATH 中没有 pidof，/bin/sh 是 Bash。旧实现把命令失败当作未找到相机，可能错误回退；127 返回模型复现了该缺陷，但 USB 记录不能直接证明当前相机运行环境里一定没有此命令。

本次三项修复
1. 激活交接移到 /run 内存目录；发起方 exec 释放旧 SD/内部盘脚本描述符，独立服务使用 IgnoreOnIsolate=yes 和非阻塞恢复请求。正常终止保留待验证状态，明确的启动/恢复命令拒绝则记录失败。下一次启动仍必须验证 boot id、加载器、对象映射和实际内存字节，绝不把“请求已接受”当成“激活成功”。
2. ARM 检查器直接扫描 /proc 的精确可执行文件路径及进程启动时间，再将 PID+启动时间传给库校验。唯一进程、无进程、多进程、无法读取分开处理；无法读取或存在歧义不会触发恢复原厂库。
3. 接续这台相机已记录的 R11f6 失败状态，校验旧包、状态历史、已注册服务及完整备份 SHA256。只退出已确认归属的旧 wants 链接，将链接保留在新目录；旧包、旧状态、旧服务文件和完整备份全部保留。未知内容拒绝接续，部分链接搬移失败会恢复旧链接。另存一份本轮完整备份。兼容旧激活目录已随恢复启动消失、但精确 SD 记录和服务归属仍能验证的情况。

变更边界
RTOS、event10、bit6、首末绑定、采样器、菜单和 HEVC A/B/A 实验实现保持字节一致。库事务及启动服务除版本路径外保持一致。本包解决激活障碍，不宣称解决 30p 帧率瓶颈。不重做码率或 CPU/BUS 对比。

验证边界
ARM 测试运行实际编译指令，内核、/proc、块设备、X11 端点被建模。流程测试执行真实 shell、文件、链接及实际终止信号，systemd/进程/完整备份端点被建模；其中完整备份算法另以真实 ARM 执行完整 157285888 字节及末字节损坏测试。未在真实相机上执行 R11f7，不能用离线测试证明硬件激活或帧率提升。
原 SD 64 项既有枚举错误单独保留，没有文件系统修复；不据此认定它们是激活根因。
