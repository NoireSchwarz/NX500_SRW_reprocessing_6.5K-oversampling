# 当前状态 2026-11-10（R10k 实测后）

R10k 已完成机上三模式对照。实际安装清单与包一致，记录完整；原生 DCI24、原生 UHD29.97、全宽 UHD29.97 三段共 1623 帧均成功解码，累计源送帧与文件帧数逐段完全吻合。

| 稳定录像模式 | 提交→完成 IRQ | 整周期 | 最终 IRQ→回调 |
| --- | ---: | ---: | ---: |
| 原生 DCI24 | 33.10ms | 41.67ms | 5.32µs |
| 原生 UHD29.97 | 31.18ms | 33.36ms | 5.55µs |
| 全宽 UHD29.97 | 43.61ms | 44.17ms | 6.08µs |

全宽录像前／后取景的提交→完成 IRQ 约 32.65／32.99ms。录像时开帧事件约在提交后 0.03ms 出现，长耗时集中在开帧之后到最终完成 IRQ 观测之前；回调→下一提交约 0.47ms。这里的 IRQ 时间包含观测延迟，不能当作纯硬件忙周期。

全宽每 10 个处理帧仍有尖峰，但去掉峰值相位后，普通帧提交→IRQ 仍约 42.36ms、周期约 42.87ms。补帧开关只能辅助验证峰值，不能用减少补帧或修改时间戳代替实现真实 30 个新帧/秒。

本轮全宽视频为 446 新帧 + 45 补帧 = 491 帧，音频时长 19.6693s，视频按固定 29.97p 编排为 16.3830s，相差 3.2863s。整段按音频时长折算约 22.675 新帧/秒、24.963 编码帧/秒，仍存在实际供帧不足。

EP 回读的被动对照已完成：原生 DCI、原生 UHD、全宽 UHD 的稳定取景／录像都存在相同的 720 字节步幅、8 位 RDMA1／WDMA1 配置。当前证据不支持“全宽录像新增了一路独有的回读配置”；相同配置不等于相同实际访存，不能据此宣布所有 EP 影响已排除。原厂可恢复的辅助关闭入口仍未确认，**未实现 EP bypass 开关 A/B**。

0x43 的实际录像回调地址已确认，独立 SRAM 更新等待路径与当前录像通知路径也已区分。全宽相邻请求的 252 组首事件间距均符合约 33.37ms 输入节拍及一次／两次事件计数，双事件更符合输入更新跨过较长处理窗口；不是已证实的加载重试或“等待16ms”。

七份稳定快照的 DDR_A 读回均为 700MHz；各模式在取景／录像之间没有所记录时钟选择字或 DMA 控制参数的错切。原生与全宽使用不同选择字，不能把它们当作相同实际时钟。此前 CPU performance 和单一 HEVC 桥接值 0x14A 对照无改善，不能据此排除全部访存争用。

记录器进程 CPU 约 0.355%，无采样截止期丢失；约 120.7s 首次记录到 500ms 周期，此后环覆盖不足，有 200 个原生序号缺口。这是观察器丢记录，不是相机掉帧。所有阶段保留边界剔除、采样覆盖和不同目标码率（原生70／全宽80Mbps）的限制。

下一步应对齐同一帧的 IPC DMA／核心完成、EP 主输出 WDMA2 完成及 HEVC 提交／完成，区分并行访存变慢与输出信用／内部握手反压，并统一原生／全宽目标码率进行控制。只继续读取同一组全零 IRQ 状态无法确定阻塞子段。

持续掉帧尚未解决；不可改变的硬件上限尚未证明。保留已生效的蓝边修复；本轮仅发布诊断文档，未修改相机程序或 SD 卡。SRW 主流程的已实现状态不变；实机 Log／连续视频 Gamma 尚未实现。
