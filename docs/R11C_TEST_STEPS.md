# R11c 帧尾与并行表面：一次合并短测

这是检查包，观察 RSZ2／WDMA2 帧尾及其与 HEVC 另一表面的推进关系。没有修改性能路径，尚未证明帧率改善。不重复码率测试。

1. 安全弹出 SD 卡，装入相机完成安装。完整关机再开机，断开 USB，确认视频补丁页显示 **R11c TAIL OBSERVER**。
2. 照片模式应用 **FULL WIDTH 4K 30P**，按提示在原厂菜单重选 NTSC／UHD30p／PRO，再回照片模式。沿用原码率、默认 QOS 和曝光设置。
3. 开启 **STAGE COUNTERS**，确认 **ON / STOP+SAVE**。照片模式等 **5 秒**，检查菜单和按键响应。
4. 视频取景 **35 秒 → 录像 120 秒 → 停录后取景 35 秒**。保持构图稳定，在画面底部左、中、右都有适量运动细节，避免只移动左半边或完全静止画面。
5. 回照片模式，停止并保存采样。**必须看到 COUNTERS SAVED - SAFE TO CONNECT USB，再连接 USB。**

只需这一段合并采样，不另加码率或原生4K对比。若全宽应用或采样启动报错／卡死，保留最新日志和目录，不反复应用。

保留新 VIDEO_STAGE_* 的 READY、DONE、counts.bin、frame-flow.bin、hevc-flow.bin、buffer-flow.bin，以及对应 MP4、安装日志和 VIDEO_FULL_*。照片、录像、原固件与历史日志均不要删除或移动。HEVC 断点停用提示正常。

下轮先确认安装 `recovery-r11c-tail-parallel` 与实际采样 `R11c TAIL_PARALLEL` 一致，再核验 buffer schema5。重点检查：完整 HEVC 锚点是否仍合格、底行六个左／中／右探针和只读状态覆盖、跨请求过渡是否单列、同一Linux时钟上的写入／取结果路径／请求头切换先后，以及CPU退让后的窗口长度。

密集帧尾记录不保存线程栈，不能单独算作 HEVC 等待命中。跨请求变化不能混入正式同请求统计；指纹变化也不是整帧 EOF，原始状态位和另一表面活动不能当作 DDR 流量或争用时间。
