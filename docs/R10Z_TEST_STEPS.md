# R10z 合并观测测试

用途：一次部署、一次连续采样，尽量把 bit6→bit2 的约 43ms 区间缩小到输出写入、HEVC 完成等待或两者重叠的区间。此版尚未证明提升帧率。

1. 把 SD 卡装回相机，完成安装。完整关机再开机，断开 USB。视频页应显示 **R10z STAGE WINDOWS**；只部署到 SD 不代表相机已安装成功。
2. 保持 NTSC、UHD30p、PRO，沿用原有正常码率和 BUS QOS 设置，不做码率或 QoS 对比。在照片模式应用 **FULL WIDTH 4K 30P**，按菜单提示重新选择原厂 UHD30p／PRO，再回照片模式。
3. 启动 **STAGE COUNTERS**，确认显示 **ON / STOP+SAVE**。照片模式等待 **5 秒**。
4. 进入视频取景 **35 秒** → 录像 **120 秒** → 停录后保持视频取景 **35 秒**。使用光线稳定且有适量运动细节的场景，录像中间可以缓慢移动构图数秒；不需要更改曝光、焦距或其他参数。行指纹不变本身不代表流水线停顿。
5. 回照片模式，停止 **STAGE COUNTERS**。必须等到 **COUNTERS SAVED - SAFE TO CONNECT USB** 才连接 USB。保存前不要连接 USB，也不要启动第二次采样。
6. 保留最新 `VIDEO_STAGE_*`、对应的 `VIDEO_FULL_*`、安装日志及本次 MP4。若开始、应用或停止失败，记录发生在哪一步及屏幕原文，不删除失败目录。

正常保存仍为四个采样文件：`counts.bin`、`frame-flow.bin`、`hevc-flow.bin`、`buffer-flow.bin`。最后一个文件采用 schema 2，包含阶段窗口、映射及线程校验、独立开销账本和最多四个内存快照。没有第五个采样文件，也不要求多次拍摄。

PC 分析入口：`python -B -X utf8 work/r10k-ep-flow/tools/analyze_r10z.py 路径/VIDEO_STAGE_目录 --out 结果.json`。分析器会先检查 READY／DONE 和文件完整性；实际相机运行版本必须以安装日志和新采样目录中的运行标识共同确认。

默认每 5 秒一个细观测窗口，每窗最多 80ms、录像最多 26 个向量，目标间隔 2ms。超预算会降低细观测频率，100ms 原有环读取优先。RSZ_OUT2／WDMA2 EOF 在原厂未启用时明确记为不可用；HEVC 未找到合格等待线程、内存快照未完成或输出面校验不通过时也保留失败信息，不能据此判定该阶段没有耗时。
