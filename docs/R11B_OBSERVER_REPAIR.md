# R11b：原厂等待点联合识别与底行右边缘

## 本次依据

R11a 实机安装和采样均已确认。稳定录像普通周期约 41.4318ms，全部周期均值约 42.5344ms；bit6→bit2 均值 42.0206ms，完成至下一请求约 0.4802ms。相对 29.97p 的 33.3667ms 预算，普通周期仍需回收约 8.0651ms。现有数据没有把这段精确拆成 RSZ2、WDMA2、HEVC 或 DDR 时间。

R11a 取得 386 个细向量，384 个首末请求匹配，278 个严格 Que／HAL／映射关联。100ms 快读 2080 次，最大间隔约 110ms，未发现覆盖丢失。四次内存快照完整；录像连续空闲／总空闲均 98.171875MiB。这些是 Linux 可见快照，不证明 RTOS 缓存发布、带宽或可重分配能力。

R11a HEVC 合格等待为零。保存的 30 个候选原始系统调用号均为 0，PC 却落在原厂 pthread 的普通条件等待或 write 返回点；这些线程的 futex 地址与 HEVC 对象不符，绝不能补标成 HEVC。354 次完整成对 HEVC 信号量读取中有 280 次计数前后都为负，只说明对象处于等待状态，不给出等待线程和计时链。

原固件 kernel.Image 的 collect_syscall 从 thread_info+0x4c 取得编号，同时从用户寄存器帧取得参数、SP、PC。普通 vector_swi 路径未见同步更新该编号；syscall_trace 会更新。5 组真实 ARM collect_syscall／memcpy 回放复现了原始编号为零或旧值、寄存器帧仍指向有效调用点的情况。运行内核未直接哈希，此结论的适用性由原固件反汇编和相机 PC 证据支持，不能把模型 thread_info 输入写成实测值。

## 生产改动

仅重建 Linux 采集器与菜单。当前 RTOS、fullwidth helper、event10、bit6、首末绑定及其 21 项固定哈希保持原样；无新增 RTOS 分配。100ms 环、三段细窗口及有界冷映射扫描、同请求 pending 最多两次补读、四文件停止后导出均保留。总 RAM 数据文件仍为 18,560,000 字节。

1. **保留原始编号。** schema4 分别保存前后原始值与是否相等，只有独立判定通过才额外输出 inferred_syscall=240；绝不覆写原始字段。前后编号变化本身不会抹除有效的 PC／寄存器／对象证据。
2. **联合判定。** 已验证原厂 libpthread SHA256 为 `83aaaa614344f4d28047358eb7ce49665439bd7149bd17ad9fc1846a309abe9e`。候选必须位于基址+0xbd04；前后各读取原厂+0xbce8 的 32 字节，严格比较 mov r7,#240、SVC 及邻接指令；匹配同一个 HEVC 信号量 wrapper／backing+12、负计数及 FUTEX_WAIT。线程 TID／starttime、参数／SP／PC、相机／source／HAL 类型、原厂描述符、fd readlink 和栈中 +0x2cc74、+0x260d0 两个返回 PC 都要通过。实际选中和正向细向量再次读 starttime。栈是有限扫描，不声称已可靠展开完整调用栈。
3. **拒绝可审计。** 保存完整 8 指令字 A／B、读取掩码、前后原始线程视图、对象／HAL 描述符、明确拒绝位。普通 condwait(+0xb980)与 write(+0xee04)仅作为拒绝证据。每 100ms 至多检查一个线程；保留正命中、同一 inventory 中新的拒绝状态、每16个／最后一个里程碑，避免填满元数据。
4. **六个输出 RAM 探针。** 保留 Y 顶行、Y 中行、Y 底行、UV 底行左侧 byte16 的 16 字节指纹；增加 Y 底行2159与 UV 底行1079的 byte3824..3839，即最后16字节。严格检查 3840 stride／2160 Y／1080 UV、类型7、成对 WDMA 配置和物理边界。仅 Linux PROT_READ 映射，页缓存32增至64（最多256KiB已分配输出内存的只读映射），并验证观察上下文仍小于8192字节。未增加 RTOS／CAP 图像内存。
5. **schema4 解码与证书关联。** 热向量新增指令指纹、拒绝标志和两个右端指纹；复用原来四个重复字段，原始计数／状态仍各保存一份。最终等待还必须匹配此前选中证书、前后完整映射、首末绑定、Que 代际及 HAL 物理地址。缺少任何一项保留原始记录，禁止推导 HEVC 等待时长。旧 schema1/2/3 不做追溯推断。

真实 ARM 代码、原厂库指令及原厂等待链回放，联合判定的正负端点矩阵，完整合并运行、停止保存、USB 退出、映射失败、六探针边界与解码假证据测试，均需通过后才能部署。历史 R10r..R11a 相机文件只读回归，不能追溯补全缺失观测。

OS、DMA、缓存一致性、内核设备与调度边界仍有模拟部分；本轮不能证明相机硬件无卡死、HEVC 新观测已实机命中或帧率提高。此包没有性能路径修改，没有重做码率测试，没有开启 IRQ、修改 ACK／选择器、ptrace、断点、打开 codec 设备或写像素。

## 判读下一次结果

- 六探针及关联有效，右端明显晚于左端：进一步收紧最后可见写入区间，仍不能把探针当作 EOF。
- 新联合等待命中：按同一缓冲代际的连续细向量，观察写入和原厂完成等待是否重叠。等待包含 IRQ／调度，不直接给出纯 HEVC busy。
- 联合等待未命中：按拒绝阶段区分 PC、运行中字节、对象、返回栈、生命周期或观察时机；不能将零命中解释为零 HEVC 耗时。
- WDMA 输出仍与 HEVC 前一缓冲交错时，继续保留跨请求候选与 Que 元数据归还原值。地址复用、DDR争用和减少重叠的性能修复仍须对应证据支持。
