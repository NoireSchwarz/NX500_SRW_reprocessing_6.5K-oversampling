# Sources, build information and licenses

The eye detector adapter is an independent contribution by NoireSchwarz, licensed under AGPL-3.0-only. See `source/eye-af`, including its build and Cortex-A9 regression tests. Building this directory with Zig 0.13.0 reproduces the distributed library.

The optional installation workflow originates in the [NX500 development project](https://github.com/NoireSchwarz/NX500_SRW_reprocessing_6.5K-oversampling). The shell programs under `nxl-eye-image28` are their source. The two small activation text files follow the existing Metol SD installation layout. No Samsung camera executable, firmware, personal photograph, or per-device boot image is distributed.

- The file comparison utility is in `source/fileops`. The single-use process claim helper and passive LCD observation helper are in `source/helpers`. These static ARM programs target Cortex-A9 with Zig 0.13.0 and musl. For example, the claim helper builds with `zig cc -target arm-linux-musleabi -mcpu=cortex_a9 -static -O2 -Wall -Wextra -Werror -o claim.arm postflash-claim.c`. The public build omits its debug records. The live camera package and the public package have equal allocated section contents for this helper.
- The wake service is Vasile Dumitrescu's **nx-on-wake**, GPL-3.0-or-later. Its corresponding C source and upstream credits are in `source/helpers`. The unit itself is `nxl-eye-image28/wake-unit`. See `licenses/GPL-3.0.txt`.
- The notice program is the project's existing AGPL-3.0-only camera menu. The installer invokes its single fast-start notice. Its corresponding compile inputs are under `source/notice`. Within `base/nx-lut-lite` use `python tools/build_zig.py --menu-only --zig <path-to-zig>` on a PC with GNU nm/readelf, or add `--elftools-path <pyelftools-installation>`. The distributed ARM program has the camera-tested machine code. One path string used by a QR-code assertion was anonymized without changing its length. QR Code generator notices (Project Nayuki), X11 headers and font license texts are retained with the sources. For the project license see `licenses/AGPL-3.0.txt`.
- Musl and Zig notices are in `licenses`. The on-device software uses the camera's existing system libraries.

The Windows staging tool requires the user's own drive and volume serial. It refuses to run with assertion checks disabled. `checksums.json` covers every camera installation component. The independent public packaging changes were checked on a simulated SD volume. The hardware evidence for v2.8 applies to the distributed eye library and the original rebuild workflow on one NX500.
