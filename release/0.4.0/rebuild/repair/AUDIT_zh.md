# Unified R1 快启软砖调查

核对的公开 ZIP 是 `NX500_Full_Mod_EyeAF_0.4.0.zip`，SHA-256 为 `49de7be7e19899526556178e386b5beafb43c2049f43ebf51b7b41e33e5fe766`。本次反馈描述相机应用无法启动、按快门会直接黑屏。仍缺少故障机那次安装的准确步骤、回执及相机进程日志。社区另有在 NX LUT Lite 上叠装 `nx-on-wake` 后软砖、原厂恢复成功的记录。[社区原始报告](https://www.reddit.com/r/SamsungNX/comments/1y5wexh/samsung_nx500_hidden_recovery_mode_discovered/)

## 可核实的风险路径

1. 社区独立 `nx-on-wake` 与旧 R1 首装占用 `/usr/local/bin/nx-on-wake` 和 `/etc/systemd/system/nx-on-wake.service`。独立安装器以覆盖方式写这两个文件、启用服务，随后直接切入原厂重建。机身只会以当时有效的服务关系保存快照，叠装有可能把另一套入口留在旧快照之外。[独立安装器源码](https://github.com/ottokiksmaler/nx500_nx1_modding/blob/master/nx-on-wake/install/install.sh)
2. R1 首次安装说明先要求执行旧 `EYE`，再执行 `REBUILD`。第一轮已切入重建，联合恢复服务与写镜像前核验在第二轮才安装。两种安装步骤的保护程度不同。
3. R1 的 `REBUILD` 把上一代运行目录整体改名，再写入同一绝对路径。旧快照仍可能按原路径查找旧状态。在三星原厂 ARM 服务管理器回放中，模拟 R1 在写镜像头前拒绝继续时，卡灯触发和 zram 已启动，原厂相机启动等待用的 `/tmp/.hib_ready` 未发布。R1.1 对同一失败条件保留了镜像头，清理已启用的 zram，并发布了该就绪标记。故障机是否命中这条路径仍需那次日志确认。

## R1.1 修正

- 首装和已认出的 R1 使用同一份受保护的原厂重建流程。对照机身固件、主模块、原厂与补丁启动关系以及存储状态后，才开始暂存候选。未知的独立启动入口会停止，旧路径和日志保留。
- 候选对焦库与状态保存在独立目录。引导脚本匹配本次写入的回执或已恢复进程的声明后才选择候选。旧 R1 的运行库和启动声明保留，原厂基线走原厂相机入口。
- 原厂写入服务在触碰 zram 和卡灯前先核验实际服务管理器。写镜像头前再次核验，拒绝时回到原厂的就绪标记。此前的镜像头和原始快照备份都保留。
- 两个选项各自校验库哈希。YuNet Focus2 文件与已在开发机短测的版本逐字节一致。新共用安装器还需要实际开机确认。

R1 的 Eye AF v2.8 等待与相机进程匹配的恢复标记，之后才开始使用眼部定位。现有证据无法断定快门黑屏时是否已经走到这里。电脑回放覆盖安装器、文件回退、启动选择和原厂 ARM 服务管理器。模拟镜像写入采用内存标记。实机验收还要分别检验半按取景和全按拍照。复现问题时，请在保留原卡的前提下提供本次 `NXDEMO51/FAST_START_EYE_AF_ROOTLIB_*`、安装 ZIP 的 SHA-256，以及最后可见的提示。
