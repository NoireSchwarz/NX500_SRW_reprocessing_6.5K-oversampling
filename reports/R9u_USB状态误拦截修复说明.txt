R9u — USB 状态检查误拦截修正
2026-11-09

本轮现场证据
安装日志显示 R9t 已完整安装，机内模块清单 d96727b48cdaf591af7da576284604b468187c9fdccb25c2c9dcf1a427cf9de2 与部署包一致。
启动日志明确记录 USB_CONFIG_VALID_BASELINE_SAVED，说明原厂持久 USB 配置可读、基线已保存；这次不是没有装上。你确认切换视频模式时报错时没有接任何 USB 线，且实际 USB 连接正常。
卡上没有后续 usb-state.log。R9t 的导出本身依赖同一个软件事件检查，导致它失败时也丢失了失败摘要，无法从旧卡日志确定当时具体是读取错误还是事件值滞留。

已确认的设计缺陷与原厂对照
R9t 把 memory/sysman/usb_status 软件事件的读取成功及数值作为视频操作必过条件，缺失／异常／滞留事件都可能挡住实际未接线的相机。
原厂插件 OEM_sys_get_jack_usb_online 使用 sys_get_int 读取 /sys/class/extcon/USB/state。原厂 OEM_sys_get_usb_state 在物理状态为 0 时，即使软件事件值为 1/2 或读取失败，也返回未连接；已执行原始 ARM 函数验证。
因此 R9u 改为以原厂物理插入检测点为准：连续两次读到 0 才放行，1/2 仍拒绝视频修改，读取失败或变化中也拒绝。软件事件只作诊断，不再单独阻止未接线时的视频切换。
实际接线的情况采用保守策略，切换模组视频配置前请拔线；不把软件事件 AVAILABLE 解释成允许忽略物理插线。

本包修改
USB 助手和手动记录器共用新的物理端口判断。读取 sysfs 的文本值，不根据其常见的 4096 字节文件元数据去判断内容长度；软件事件也移除了不必要的文件尺寸上限。
沿用 R9t 的有效 USB 基线格式、文件身份约束、原厂记录锁、损坏样本保存和同步／回读恢复流程，已有备份在升级中保留。不会重置 USB 配置默认值。
新增日志字段：usb_physical、physical_errno、usb_event、event_errno、event_tag、event_raw、event_bytes。物理确认未插线时，早期检查失败也会尝试写入一行 SD 摘要，不再让软件事件失败把诊断导出一起挡掉。
菜单对物理端口读取失败单独提示 USB PORT READ FAILED。启动输出也带有完整状态字段，便于从 startup.log 定位。
仍无新增常驻轮询；原厂视频助手、全宽 RTOS 配置、80Mbps、SRW/LDC/Gamma/JPEG 和共享工作区保持原样。

电脑端验证
51 个实际 ARM USB 助手场景，包括原有截断恢复／失败回滚限制，以及软件事件缺失、滞留、异常、空值、扩展长度、物理状态读取失败和插拔变化。
同一份“持久 USB 配置正常、端口未插入、软件事件缺失”输入，原部署 R9t 返回 USB_STATE_UNAVAILABLE，R9u 正常放行且没有写入原厂配置键。
原厂物理检测与 USB 状态函数已回放验证；手动记录器的启动、插线退出及状态失败退出也执行了实际 ARM 代码。包装／菜单、完整运行时与 R9t 升级备份保留另附验证记录。
以上不替代本轮机上确认。此前 30p 与 USB 持久坏键的首次触发链仍未证明，本包针对的是这次新增状态检查误挡。

机上步骤
按原方式安装 R9u，关机再开机，确认菜单显示 R9u。无需重刷原厂固件，也无需手动删除或重新初始化已有 USB 基线。
先不接 USB 线，进入 VID 读取状态并切换配置。全宽录像仍需机身 NTSC / UHD30p / Pro，应用后暂选其他尺寸再切回 UHD30p / Pro 使原厂重载。
正常时日志应出现 usb_physical=0；usb_event 不可读或滞留不会因此阻止切换。若仍失败，保留 NXDEMO51/logs/usb-state.log 和 startup.log，新的字段能区分具体读取环节。
