R9t — USB 持久坏键保护与回归分析
2026-11-09，本地待部署测试包，尚未上机

这次做了什么
在 R9s 的 80Mbps、取消自动高频取证基础上，加入 USB 配置的有效值备份、受限恢复和操作边界记录。目标是处理“配置被截断后，关机重启仍不能连接”的已复现故障模式。不是已经证明 30p 的全部 USB 问题都已根治。
SRW/LDC/Gamma/JPEG 引擎、192MiB 工作区、原厂视频助手和全宽 RTOS 配置保持 R9s 的相同二进制；新增 USB 助手并更新菜单／启动包装。没有改写原厂 VCONF 库、USB sysfs、deviced 或其他系统服务。

比上一轮新增的固件证据
原厂 libvconf 的写入顺序为：写锁 → 清空键文件 → 缓存写入类型和值 → fflush → fdatasync → 解锁 → fclose。
其 ARM 代码没有检查 fflush 和 fclose 的失败结果。模型中令缓存刷新失败、fdatasync 对尚未写入的数据返回成功，就能复现“函数返回成功、键文件却为空”；再运行原厂读取函数得到现场相同的 -22/errno11。
这个实验确认原厂存在漏报写入失败的路径，不证明本机当时一定空间不足、掉电或发生了某个特定 I/O 错误。
已定位到 USB 持久模式键的原厂写入位于 deviced。码率助手暂停的是相机应用，两者是不同进程，因此没有证据支持它直接暂停了 USB 写入者。30p/100Mbps 与持久键异常之间的具体触发关系仍未确认。
25fps 正常、旧记录器运行时 USB 曾成功，继续作为对照保留；记录器不再作为这次根因的主要解释。30p 版修正读取后首次真正执行的码率路径仍是回归重点。

恢复的严格条件
先在 USB 正常时读取并保存该机原厂的有效 8 字节模式键，含文件身份、权限及校验；支持值来自原厂 XML 的 0/1/2/10，不猜一个默认值覆盖。
仅当现有键确实缩短为 0–7 字节、类型头前缀仍吻合、文件身份／所有者／权限与有效备份一致，且 USB 已断开时，才尝试恢复。使用与原厂协作的文件记录锁，原厂持锁或状态无法确定时拒绝改写。
恢复前持久保存损坏内容；在同一个文件上直接写回已验证的有效字节，保留锁、文件身份、权限与通知对象。检查每次写入、同步和回读的结果，避免“失败却报成功”。
缺少有效备份、备份损坏、文件已替换、类型不符、未知固件、USB 正连接或 I/O 仍失败，都不会猜值修复。正常原厂模式变化会更新备份。

执行位置与日志
启动正常监听器时检查一次；进入 VID 状态，以及尺寸重映射、码率修改、全宽应用和恢复的每个边界再检查。原厂视频步骤失败后也会检查。没有新增循环监视进程，也不在录像中周期刷新、同步 SD。
正常时先启用一次蓝牙／mod 菜单，才能建立备份。若以后出现同类 USB 故障，可拔线后重新进入 VID 读取状态；符合上述条件会自动恢复。启动检查失败仍保留菜单可用，但 VID 修改会被阻止并显示 USB 检查错误。
主要备份、损坏样本和完整事件在机内模块的 state/usb-config；USB 断开时，把每个检查点的一行摘要写到 SD 的 NXDEMO51/logs/usb-state.log，写完即关闭。连接中不导出到 SD。
检查点包含时间、操作阶段、键的原始字节及文件身份；并核对原厂 VCONF、USB 支持表和视频相关库的文件哈希，便于追查到底在哪个边界变化。

明天的验证顺序
安装 R9t 后彻底关机再开机，在当前 USB 正常的情况下启用一次蓝牙／mod，让它保存有效基线。无需手动新增测试菜单项。
先保持机身原生 NTSC / UHD30p / Pro70，不应用全宽，检查 USB；断开后再应用 FULL WIDTH 4K 30P，暂选其他视频尺寸再切回 UHD30p / Pro，使原厂重载 80Mbps，再录像检查。
若 USB 异常，先拔线并进入 VID 读状态，随后保存 usb-state.log，观察是否出现 RECOVERY_VERIFIED。这样能区分“已确认的坏键自动恢复”与“实际另一个 USB 故障”。

电脑端验证及限制
实际部署 ARM 助手已覆盖 40 个场景，包括所有截断长度、跨进程重复恢复、原厂模式更新、写锁占用、备份／写入／同步失败、连接中拒绝、不同文件身份及固件拒绝。恢复字节也交给原厂 ARM 读取函数验证成功。
真实包装脚本验证了步骤前后检查、原厂步骤报错后仍检查、USB 检查失败时阻止后续写入，以及启动检查失败后菜单仍可打开。完整包另做身份、运行时、全新安装、R9r 升级及备份保留检查。
这些是原始代码／ARM 回放与模拟文件系统故障测试，不替代实机验证。尚不能承诺所有 USB 故障一劳永逸消失，也未证实 30p 首次触发异常的完整因果链。今晚没有访问相机或写入 SD。
